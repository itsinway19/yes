0. قرار البناء في صفحة واحدة

  1. المعمارية: Modular Monolith في Laravel / PostgreSQL / Vue / TypeScript مع وحدات مملوكة بالمعنى وقواعد العمل، ما دام لا يظهر سبب قابل للقياس يبرر التوزيع. SQL/RLS والسلطات الفعلية لا تُنقل إلى Vue أو أسماء المجلدات.
  2. أربع هويات مختلفة: Goal نتيجة يطلبها النشاط؛ Value المنفعة التي يقدمها BuilderAd؛ Function/Use Case العملية التي تقدمها؛ Capability عمل تخصصي تعيد الوظائف استخدامه. Lever موضع تأثير، وMethod طريقة تنفيذ قدرة. لا ندمج الهويات أو ننشئ Class لكل عنصر بحثي.
  3. ثلاثة مسارات أدلة مستقلّة تتلاقى: إثبات المعرفة المطلوبة؛ وإثبات وجود طريق توظيف/تدخل مؤهل؛ وإثبات النتيجة بمرجع موثوق. وجود أحدها لا يثبت الآخرين.
  4. العلاقات متعددة الأطراف: قدرة تخدم عدة قيم ورافعات، ووظيفة تستهلك عدة قدرات، ومعرفة تُستهلك عبر أكثر من مجال. المالك واحد للواقعة/المنهج/العملية، وليس بالضرورة «مديرًا» واحدًا لكل واجهات المنتج.
  5. القرار التجاري ليس اختزالًا في الإعلانات: قد تكون أفضل خطوة تحسين العرض أو السعة أو المتابعة أو الاقتصاديات أو عدم التدخل، أو سؤالًا واحدًا مرتفع القيمة قبل الإنفاق.
  6. الأمن حد تنفيذي: Authorization ≠ Data Rights ≠ Feature Entitlement ≠ Quota ≠ Technical Eligibility ≠ External Action Approval؛ يُعاد فحص المطلوب في وقت استخدامه وعند التنفيذ المؤجل.
  7. الحاضر ليس سقف التصميم: نحتفظ بالكود الصحيح، ونغير حدودًا أو واجهات أو وظائف حين تبرر أدلة الجودة ذلك. لا ننشئ مخزنًا أو نظام سلطات موازيًا.
  8. المخزون البحثي ليس Backlog: الرافعات 15، القيم 18، الأهداف المرشحة 37، القدرات 104، العلاقات 26، والمرشحات الأخرى ذات نطاقات تعريف مستقلة. ليست أعدادًا مستهدفة للمجلدات أو الجداول أو الإصدارات.
  9. المرحلة التالية محددة: مطابقة المالكين والعقود المحلية؛ تصحيح الموانع التأسيسية المثبتة؛ تنفيذ مسار قيمة كامل؛ ثم مسار من مجال مختلف يعيد استخدام قدرة أو دليلًا دون نسخه؛ وإغلاق بأدلة اختبار.
  10. لا تعقيد احترازي: لا Microservices أو Plugin Runtime أو Universal Capability/Lever/Workflow Engine أو Graph عالمي أو Event Store عام أو منصة AI Agents قبل الحاجة المبررة والمستهلك الفعلي.

أشكال العلاقات الأربع الأساسية ليست مترادفة: DATA_DEPENDENCY = الاستهلاك المؤهل لمعلومة؛ EXECUTION_DEPENDENCY = شرط تشغيل؛ POTENTIAL_INFLUENCE = فرضية تأثير تحتاج اختبارًا؛ VERIFIED_CAUSALITY = علاقة سببية مثبتة وفق تصميم مناسب. وقد نحتاج RESOURCE_CONFLICT عند تنازع ميزانية أو مخزون أو موظف؛ لا تختزل جميعها في depends_on=true أو Graph عام.

البرمجة لا تفرض هذا الرسم كسلسلة تمر بها كل وظيفة. قد تقدم قدرة معلومات فقط، أو تدعم خطوة يدوية، أو تمتنع، وقد تستهلك نتائج متخصصة دون قضية Commercial Case شاملة. يسجل سياق القرار المؤثر حين يوجد قرار أو خطة مؤثرة، ولا تُخلق سجلات وهمية عند كل قراءة بسيطة.

مرجع النتيجة المؤهلة. عند عبور نتيجة بين المجالات يعرّف مالكها نوعها وإصدار عقدها ومرجع نسختها، ويقدّم دلالة المقدار والفترة والنطاق والتغطية والمنهج وعدم اليقين حسب نوعها. يحدّد المستهلك النشاط والممارسة والعرض والهدف وإصداراتها ذات الصلة والسوق والفترة والغرض والعملية والمستلم. تؤهل واجهات المالك المراجع والحق الحالي، ويثبت مالك حالة الاستعمال قاعدة التوافق وإصدارها. الاختلاف المادي في الوحدات أو الموضوع أو مجال الانطباق يحتاج تحويلًا مؤهلًا أو امتناعًا مفسّرًا.

الحفظ وإعادة التأهيل. يربط القرار المركب المحفوظ إصدارات السياق والمدخلات والتبعيات المادية وقاعدة التوافق والأسباب، بأقل حمولة تسمح بها الحقوق. تُعاد أهلية الاعتماديات عند الحفظ وبعد انتظار مؤثر وعند الاستعمال المؤجل. التصحيح أو السحب يعيدان تأهيل المعتمد عليه، وتُطبَّق سياسة الاحتفاظ والإخفاء في العرض التاريخي. يُستخدم حد المواد القائم حيث يلزم حق استعمال مصدر. ترخيص العرض لا يجيز التركيب أو النقل.

الأثر والنتيجة. التفويض محدد بالمقصد والعملية والنطاق والمدة. تثبت نقطة قبول الإحالة المحلية وترتيبها مع السحب، وتُربط بصمة الحمولة بمعرّف أمر ثابت. فقد الرد يؤدي إلى حالة مجهولة ومصالحة عند موائم المزود؛ يتوقف الإرسال عند غياب ضمان التكرار الآمن. مالك واقعة الحجز أو البيع أو التحصيل يقرر معناها ونسخ تصحيحها، ويثبت التقييم تعريف القبول ونافذة النضج وخط المقارنة وحدود الإثبات.

التأسيس عند أول استعمال مركب. يثبت عقد المرجع والتوافق قبل نشر أول قرار مركب محفوظ، باختبار مخرجين مختلفين من مالكين فعليين، وتغير سياق وسحب حق مع الحفاظ على الاستعمال الذي بقي مؤهلًا. وظائف القراءة والتشخيص المحلية تستعمل عقود ملاكها الحالية. حالة الاستعمال تملك قاعدة التركيب، وتبقى حمولة النتيجة عند مالكها. تخدم إسقاطات العلاقات عند الحاجة الاستعلام عن حواف ذات أنواع معروفة ومنشأ محدد.

8. تخصص فهم المشتري والطلب والوصول — قرار مملوك لا محرك استهداف

DemandReach يملك تقييم طرق الوصول لا حقائق جميع المشترين ولا تنفيذ مزود إعلانات. فصل خمس أسئلة:

السؤال المالك / مصدر الحقيقة مخرج مشروع / قيد
ماذا نبيع ولمن نعتقد أنه مناسب؟ Business/Practice/Offering + تصريحات المستخدم Buyer hypothesis بإصدار، لا «عميل مثبت»
ما الحاجة والطلب والنية وسلوك الشراء؟ بيانات أو مقابلات مؤهلة، MarketKnowledge عند الأدلة السوقية، مالك نتائج البيع عند واقعتها إشارات/فئات/أدوار بنطاق؛ لا حسابات أفراد تلقائية
ما الطرق التي قد تصل إلى الطلب؟ DemandReach يستهلك الأدلة والسعة والتغطية والجدوى خيارات: بحث، شراكة، موزع، محتوى، فعالية، إعلان، بيع مؤسسي، غيرها
هل تفعيل الطريق متاح ومأذون؟ Sources + مزود/اتفاق + Execution + حقوق/امتثال READY/UNKNOWN/BLOCKED/HUMAN_HANDOFF؛ تختلف إمكانات كل مزود
هل أنتج الطريق نتيجة مجدية؟ Outcome owner + BusinessEconomics + Evaluation عقود/مبيعات/حجوزات/فرص مؤهلة مقابل التكلفة؛ لا دليل سببية تلقائيًا

عقد وصول متخصص (دلاليًا لا جدول JSON عام): OfferingRef+Version, GoalRef+Version, BuyerContext مع منشأ فرضية/دليل، QualifiedDemandRefs, RouteCandidates, RouteEligibility حسب البلد والمزود والحق والقدرة والسعة والتكلفة، Choice/Abstention/NextQuestion, VerificationPlan. يحافظ المنسق على مصادر الأدلة ونسخها ولا ينسخها، ويترجم موائم المزود فقط الخصائص التي يدعمها رسميًا عند وقت التفعيل.

فصل فئات البيع: النشاط قد يبيع لأفراد أو شركات أو متاجر أو طلاب أو موزعين أو مؤسسات متعددة الأطراف، وقد يبيع لأكثر من فئة في العرض نفسه. لا نخلط «فئة مشترٍ» بـ«شخص طبيعي قابل للاستهداف»، ولا نستنتج حساب الموظف أو المدير أو نراسل أشخاصًا اعتمادًا على معلومات غير مرخصة. تُراعى القوانين والحقوق وشروط المنصات وحماية القُصّر. قد يكون الطريق الأجدى موزعًا أو تسعيرًا أفضل أو قدرة وفاء أعلى لا استهدافًا رقميًا.

العائلات البحثية الـ34 ليست كلها وصولًا جديدًا: A التقاط طلب قائم، B تكوين معرفة وثقة، C بيع مؤسسي/قنوات، D علاقة مع عملاء حاليين، E إزالة عوائق التحويل بعد الوصول. عائلة E تعيش وظيفيًا لدى OfferStrategy/SalesConversion/FulfillmentFit حسب المالك، ولا نحبسها في DemandReach. الفهرس المختصر في الملحق هـ.

// PSEUDOCODE: maintain these semantic boundaries without inventing
// a universal interface, storage table, or alternate authority model.
function assessReach(AuthorizedContext $ctx, OfferingRef $offer, GoalRef $goal): ReachAssessment {
    $facts    = businessOwner()->readQualifiedContext($ctx, $offer, $goal);
    $evidence = knowledgeOwners()->readForPurpose($ctx, 'reach_assessment', $facts);
    $options  = reachCapability()->assess($facts, $evidence);
    $verified = independentValidator()->validate($options, $facts, $evidence);

}

9.4 تعليمات تصميم التشغيل

  • التخزين: PostgreSQL وعقود SQL الحالية ومفاتيح إصدار/معاملة، دون Graph أو قاعدة ثانية مسبقًا؛ توضع قيود Unique/FK/Check وRLS عند ملكية الجدول. لا نغير هجرات تاريخية منشورة دون خطة انتقال متوافقة.
  • التكاملات: موائم مزود وفق قدرات محددة (read, report, create, edit, verify) وليس حالة «متصل» العامة؛ المسار البشري أيضًا خيار عملي يحتاج معيار متابعة نتيجة ولا يُعلن API-ready.
  • الطوابير: لا إطلاق أثر اعتمادًا على معاملات غير ملتزمة؛ لا ثقة في إكمال أداة دون إيصال أو إعادة قراءة/مصالحة. إعادة المحاولة تحترم المعرف الفريد والسلطة الحالية.
  • الواجهة: «السوق والعملاء» يعرض قيمة فهم المشتري والوصول دون عشرات حقول الاستهداف؛ «المبيعات والتحويل» يعرض وظائف الاستفسارات والتأهيل والبيع؛ «النتائج والعائد» يستهلك نتيجة مؤهلة؛ «القرارات والتحسين» يعرض البدائل/الأثر. إخفاء عنصر واجهة لا يمثل رفضًا أمنيًا.
  • Zero-Setup: يبدأ من بيانات نشاط قليلة وهدف معقول وتوصية مشروطة أو سؤال عالِ القيمة؛ لا أرقام إعلانية أو «ذكاء سوق» بلا مصدر.

9.5 هندسة القدرات وحدود التركيب

عقد القدرة عند حد الاستهلاك يملك مجال القدرة معنى السؤال ومقياس النتيجة واختيار المنهج من الإصدارات المدعومة بحسب السؤال والمدخلات المؤهلة. يقرّر المدقق التخصصي المستقل صلاحية النتيجة عندما يتطلب الحكم تحققًا دلاليًا أو حسابيًا. يصرّح العقد بأسباب القبول والامتناع والتغطية وعدم اليقين، ويميّز عدم الانطباق عن غياب الدليل أو تعارضه أو منع استعماله. يبقى المخرج المؤقت نوعًا محليًا. إذا نُشر للاستعمال الخارجي يُثبّت نوعه وإصداره ومرجع نسخته قبل نشر مستهلكه. إذا دخل قرارًا محفوظًا يثبّت المستهلك استعماله المحدد وتبعياته ومبرره.

تسلسل قرار مركّب وتغير الحقوق

1. الوظيفة تثبّت السؤال والسياق والإصدار والعملية المطلوبة.
2. الملاك يؤهّلون كل مخرج وتبعياته. حق display لا يجيز combine أو reuse.
3. الوظيفة تقارن الموضوع والوحدة والزمن والتغطية والقيود بمنهجها المعلن.
4. قبل حفظ قرار قابل للاعتماد، تعيد بوابة الحفظ فحص الإصدارات والحقوق
   المادية داخل حد المعاملة بما ينسجم مع ترتيب أقفال المالكين.
5. سحب سابق للقبول يمنع إصدار قرار قابل للاستعمال. سحب بعد الحفظ
   يمنع الاستعمال اللاحق المتأثر. عرض التاريخ نفسه يخضع لحقوقه.
6. أمر مؤجل يعيد التأهيل عند حد الإحالة، ثم يصالح أي أثر خرج إلى المزود.

ربط التقييم المحفوظ بحقوله. حق إعادة عرض نتيجة المصدر وحدها لا يجيز كشف حكم محفوظ استند أيضًا إلى إسقاط مقيّد. يتحقق مالك التقييم من أن القراءة الحالية تجيز الأساس المربوط بالحكم قبل إرجاعه. إذا تغيّر الحق يستطيع المستخدم تقديم طلب تقييم جديد تحت حقوقه الحالية. يحتفظ السجل بالمعنى الأصلي ضمن سياسة الوصول والاحتفاظ.

نقاط إدخال القدرات المستقبلية. المنهج أو الموائم أو المنسق المحدود يستقبل حقولًا مؤهلة وغرضًا وميزانية وإصدارًا. AI يخضع لمدقق المجال وتُعامل مخرجاته وتعليمات المواد المسترجعة كبيانات. هوية الأمر وحدود التفويض وحالة الأثر المجهول شروط قبل أول كتابة خارجية. اعتماد أثر تجاري يتطلب تعريف نتيجة ونضجًا وخط مقارنة وإذن الاحتفاظ أو التعلم. الحصص والاستحقاق وأهلية المزود وحقوق البيانات وسلطة الفعل أبعاد مستقلة.

توقيت التأسيس. حد المرجع وتأهيل الاستعمال جزء من عقد كل نتيجة منشورة. حفظ القرار المركب جزء من أول حالة استعمال فعلية تحتاج الحفظ. يمكن بناء القدرات التخصصية على عقود ملاكها الحالية مع هذه الشروط. دليل القراءة متعددة المواد وإعادة عرض التقييم الحالي لا يثبت معاملة حفظ قرار مركّب أو إحالة مؤجلة.

10. الترتيب البرمجي الحاسم — من الوثيقة إلى إثبات فعلي

التتابع العمل التنفيذي شرط الإغلاق تجنّب
A — Version & Source تحقق من مسار Codex وGit HEAD وحالة العمل المحلية؛ طابق النسخ المنشورة بالمصدر المرفق؛ احتفظ بالتعديلات غير المنشورة سجل النسخة/التغييرات والمستهلكين الحقيقيين لا شجرة/Commit/PR أو مسح جديد بلا سبب
B — Ownership Reconciliation عرّف مالك كل معنى/حق/نتيجة موجود، وقارن الكود بهذا المرجع؛ عالج خطأ تصنيفي أو ازدواجًا ماديًا مثبتًا فقط خريطة REUSE / REFACTOR / REQUIRED / DEFER / REJECT بمراجع ملفات لا نقل كود لغرض المطابقة الشكلية
C — Critical seams عالج حدود القراءة والمؤشرات والقدرات والمدقق/القرار عند أول مستهلك حقيقي اختبارات إثبات اقتران مفكوك، وعزل وإصدار وحالات فشل لا واجهات عامة لا مستهلك لها
D — Real vertical slice اختر قدرة تقدم قيمة فعلية بالأدلة والحقوق ووسيلة توظيف ونتيجة/نقص معلن؛ نفذها في مالكها من سياق Business إلى نتيجة مؤهلة/خطوة عملية أو امتناع صحيح لا اختيار «الوصول» تلقائيًا لمجرد كثرة دراسة وصوله
E — Cross-domain proof وظيفة ثانية في مجال آخر تستهلك دليلًا أو قدرة مشتركة من الأولى دون نسخ أو سلطة إضافية تحقق التصحيح والسحب، النسخ، تغيير الهدف، عدم تغير غير المعنيين لا محرك Composition عالمي
F — Closure تقاعد تعليمات وثائق متعارضة بعد تتبع مراجعها، وتقرير ما نُفذ وما أُجّل وحدود الاختبار VERIFIED_WITH_SCOPE أو SPECIFIC_BLOCKER أو VERIFICATION_INCOMPLETE لا نجاح Foundation مبهم ولا فتح جولة تأسيس بلا نهاية

اختيار أول وظيفة ليس تصويتًا على اسم رافعة: درجة الملاءمة = (قيمة المستخدم المحتملة + حقوق/تغطية الدليل + وسيلة التفعيل الواقعية + إمكانية القياس + كلفة التنفيذ والمخاطر + وضوح البديل). لا نحولها إلى «نقاط» دقيقة بلا معايرة؛ استخدم مقارنة مكتوبة قابلة للمراجعة، وجرّب أولًا ما يملك أدلة يمكن الوصول إليها بحق.

نطاق الصلاحيات عند إسناد التنفيذ: الفحص والتعديل والاختبارات المحلية؛ لا Commit أو Push أو PR أو دمج أو نشر أو بيانات إنتاجية دون تفويض صريح. لا تشغيل Foundation محلي شامل تلقائيًا؛ التشغيل الموجه ثم بوابات CI بحسب أثر التغيير، وPENDING للبوابات التي لم تتوفر.
