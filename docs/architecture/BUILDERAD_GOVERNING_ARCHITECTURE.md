## 0. قرار البناء في صفحة واحدة

1. **المعمارية:** `Modular Monolith` في Laravel / PostgreSQL / Vue / TypeScript مع وحدات مملوكة بالمعنى وقواعد العمل، ما دام لا يظهر سبب قابل للقياس يبرر التوزيع. SQL/RLS والسلطات الفعلية لا تُنقل إلى Vue أو أسماء المجلدات.
2. **أربع هويات مختلفة:** `Goal` نتيجة يطلبها النشاط؛ `Value` المنفعة التي يقدمها BuilderAd؛ `Function/Use Case` العملية التي تقدمها؛ `Capability` عمل تخصصي تعيد الوظائف استخدامه. `Lever` موضع تأثير، و`Method` طريقة تنفيذ قدرة. لا ندمج الهويات أو ننشئ Class لكل عنصر بحثي.
3. **ثلاثة مسارات أدلة مستقلّة تتلاقى:** إثبات المعرفة المطلوبة؛ وإثبات وجود طريق توظيف/تدخل مؤهل؛ وإثبات النتيجة بمرجع موثوق. وجود أحدها لا يثبت الآخرين.
4. **العلاقات متعددة الأطراف:** قدرة تخدم عدة قيم ورافعات، ووظيفة تستهلك عدة قدرات، ومعرفة تُستهلك عبر أكثر من مجال. المالك واحد للواقعة/المنهج/العملية، وليس بالضرورة «مديرًا» واحدًا لكل واجهات المنتج.
5. **القرار التجاري ليس اختزالًا في الإعلانات:** قد تكون أفضل خطوة تحسين العرض أو السعة أو المتابعة أو الاقتصاديات أو عدم التدخل، أو سؤالًا واحدًا مرتفع القيمة قبل الإنفاق.
6. **الأمن حد تنفيذي:** `Authorization ≠ Data Rights ≠ Feature Entitlement ≠ Quota ≠ Technical Eligibility ≠ External Action Approval`؛ يُعاد فحص المطلوب في وقت استخدامه وعند التنفيذ المؤجل.
7. **الحاضر ليس سقف التصميم:** نحتفظ بالكود الصحيح، ونغير حدودًا أو واجهات أو وظائف حين تبرر أدلة الجودة ذلك. لا ننشئ مخزنًا أو نظام سلطات موازيًا.
8. **المخزون البحثي ليس Backlog:** الرافعات 15، القيم 18، الأهداف المرشحة 37، القدرات 104، العلاقات 26، والمرشحات الأخرى ذات نطاقات تعريف مستقلة. ليست أعدادًا مستهدفة للمجلدات أو الجداول أو الإصدارات.
9. **المرحلة التالية محددة:** مطابقة المالكين والعقود المحلية؛ تصحيح الموانع التأسيسية المثبتة؛ تنفيذ مسار قيمة كامل؛ ثم مسار من مجال مختلف يعيد استخدام قدرة أو دليلًا دون نسخه؛ وإغلاق بأدلة اختبار.
10. **لا تعقيد احترازي:** لا Microservices أو Plugin Runtime أو Universal Capability/Lever/Workflow Engine أو Graph عالمي أو Event Store عام أو منصة AI Agents قبل الحاجة المبررة والمستهلك الفعلي.

## 1. قاموس المعاني والحدود

| المفهوم | المعنى اللازم للبرمجة | ما لا يعنيه |
| --- | --- | --- |
| Business / Practice / Offering | هوية النشاط، ممارسته، عرضه، تصريحه، سوقه وقدرته المعلنة؛ مع النسخ | حقائق السوق المستقلة أو نتائج مبيعات لم يثبتها مصدر |
| Goal / Goal Revision | ناتج مقصود، تعريف قبول، نطاق، زمن ومقياس اختياري | هدف منصة الإعلان أو KPI غامض |
| Outcome / Measurement | واقعة مقبولة من مالكها، وفترة نضجها وتصحيحها | نسبة أثر سببي بمجرد الارتباط |
| Value | منفعة تجارية أو قرار أفضل يُقدمه المنتج، مع معيار فحص | مخزن بيانات أو محرك تنفيذي خاص |
| Function / Feature / Use Case | عملية معلومة المالك تُنسق قدرات وتعيد نتيجة أو امتناعًا | قدرة فريدة دائمًا، أو نفس الشيء كالصفحة |
| Capability | سلوك تخصصي بمدخلات ومخرجات وحالات رفض وعقد | تسمية لرافعة أو مزود أو خوارزمية |
| Method / Validator | تنفيذ قدرة محددة، ومدقق مستقل عند حساسية الصحة | إذن بالتصرف أو شهادة المنهج على نفسه |
| Lever | متغير/عائلة تأثير في الواقع التجاري | مالك المعرفة أو التنفيذ أو سجل دائم إلزامي |
| Qualified Evidence | تصريح/واقعة/مؤشر/استنتاج مع المصدر والنطاق والزمن والحقوق والصلاحية | حقيقة عابرة لجميع المجالات أو جمهور جاهز للاستهداف |
| Route / Intervention | طريق تأثير: بحث أو محتوى أو بيع أو شريك أو تحسين عرض/وفاء أو تجربة | تفعيل مزود جاهز تلقائيًا |
| Decision | اختيار/امتناع وبدائل وأسباب وشروط ضمن سياق وإصدار | أمر تنفيذ أو ادعاء أن الخيار «الأفضل عالميًا» |
| Execution | إذن مستقل وأمر فريد وإيصال وحالة ومصالحة | نجاح API مساويًا لتحقق قيمة |
| Evaluation / Learning | مقارنة مقيّدة لما حدث وتعلم ضمن حقوقه وحدود القياس | تدريب عام على بيانات العملاء افتراضيًا |
| Product Entitlement | استحقاق استعمال منتج وقيود الحصص والتكلفة | إذن قراءة بيانات الغير أو تنفيذ إنفاق |

**الهوية الدلالية:** معرفات الأطلس `Vxx/Lxx/Lxx-Cxx` ومحليّات `F01–F30` و`F01–F22` و`C01–C24` بحثية ذات *namespaces* مختلفة. لا تُستعمل كهوية API/DB/Subscription فعلية. لكل عقد تشغيلي يُنفَّذ لاحقًا اسم وظيفي وإصدار معجمي ومطابقة `source_namespace + source_id → runtime_contract / decision`؛ ولا تُعاد تسمية واقعة تاريخية لتتوافق مع فهرس بحثي جديد.

## 2. خريطة الملكية البرمجية

**المالك هو الجهة التي تملك قواعد صحة الحقيقة أو العملية وتقبل تغييرها**؛ ليس بالضرورة مجلدًا موجودًا اليوم. لا تُنشأ المجالات الخالية لمجرد حجز مكان.

| المجال / مسؤولية المالك | يملك | لا يملك / العلاقة الصحيحة |
| --- | --- | --- |
| **Business & Goals** | Business/Practice/Offering، تصريحات المستفيد، الغاية وإصداراتها والقيود المعلنة | لا يقرر وجود طلب سوقي أو بيع مكتمل من تلقاء نفسه |
| **Sources & Rights** | ارتباط المصادر، إتاحتها ونسخها وحقوق/أغراض الاستخدام، قدرات المزود الفنية | لا يمنح صلاحية Business ولا يحلل جدوى المنتج التجاري |
| **MarketKnowledge** | دليل سوق مرخص، مصدره وفترته ومناهج سوق متخصصة وتصحيحاتها | ليس مخزنًا عامًا لحقائق CRM/ERP أو سجل حقيقي لكل المبيعات |
| **MarketOpportunity** | تقييم الطلب والحاجة والفرص والملاءمة التجارية الأولية | لا يحوز حسابات المشترين الشخصية ولا يعلن جدوى وفاء دون قيود |
| **DemandReach** | مرشحات طرق الوصول وأهلية القناة وشروط المقارنة وتخطيط الوصول | لا يمتلك كل حقائق المشتري ولا ينفذ APIs المزود ولا يحل محل الإعلانات |
| **OfferStrategy** | مقارنة العرض والتسعير والرسالة ومقترحات تجارب التحسين | لا يمتلك التكلفة المحاسبية الأصلية أو قرار تعديل سعر مأذون |
| **AdvertisingPerformance** | أداء الحملات وإشارات التحويل المؤهلة واستراتيجيات الإنفاق | لا يمتلك أصل البيع والتحصيل ولا جميع طرق الوصول |
| **SalesConversion** | تأهيل ومتابعة وتحويل واستجابة وشراء وحجز ووظائف تشخيص الفقد | الإفادات تبقى عند مالك واقعها؛ ليس CRM شاملًا مفروضًا |
| **FulfillmentFit** | قدرة خدمة الطلب والموعد والتغطية والوفاء وقيود السعة | ليس ERP ثانيًا ولا يملك هامش الربح |
| **BusinessEconomics** | حساب السيناريوهات وهوامش المساهمة وتكلفة الوسيلة والتحصيل المؤهل | لا يخلق تكلفة أو إيرادًا دون مصدر ويجب ألا يساوي ROAS ربحًا |
| **CustomerRetention** | تشخيص الأفواج والتجديد والاستعادة والإحالات | لا يكرر سجلات البيع أو العملاء |
| **CommercialDecisions** | تنسيق البدائل العابرة للمجالات، قرار أو سؤال أو امتناع وتسجيل أسبابه | لا يملك خوارزميات كل المجالات ولا سلطة تنفيذ |
| **Execution & Security** | سلطة تنفيذ، أوامر وإيصالات ومصالحة وعزل ووصول مؤهل | لا تجعل نتيجة تحليل أو اشتراك منحًا ذاتيًا للصلاحية |
| **Outcomes & Evaluation** | تعريف قبول النتيجة وربطها بقرار/تدخل وتقييم أثر مؤهل | مصدر الواقعة يحتفظ بملكيتها؛ لا أثر سببي بلا منهج إثبات |
| **Product Access** | استحقاقات المنتج المدفوع/المجاني والحصص والاستهلاك والمحاسبة المستقبلية | لا يمنح حقوق البيانات أو تفويض Business |
| **AI / Provider Adapters** | اتصال مقيد بنموذج/مزود/أداة وترجمة قدرة متاحة وتكلفتها | لا يقرر الحقيقة التجارية أو يدير سلطة مستقلة |
| **Advertiser Experience** | التنقل والأسئلة التدريجية وعرض النتائج والبدائل وZero-Setup | لا يملك السياسة أو نتائج التحليل أو الحقيقة التشغيلية |

**فصل L01 الحاسم:** «العميل/العقد» في الأطلس قد يشير إلى علاقة BuilderAd التجارية بالوكالة أو المستفيد، وليس دائمًا إلى مشتري منتجات المعلن. لا تخلط Customer/Payer/Beneficiary في منتجنا مع Buyer/Prospect لدى نشاط المعلن.

**اتجاه الارتباط:** `UI → Domain Use Case → owning domain contracts → validated results`؛ وتتم القراءة المؤهلة بواسطة مالك الحقيقة؛ و`Method + independent validator` داخل المجال؛ وإجراء خارجي يمر عبر `Execution + provider-specific adapter`؛ ويُقرأ تحقق النتيجة من مالكها. لا استعلام عابر مباشر إلى SQL خاص بمجال آخر إلا عبر عقد عمومي معتمد ومقيد الحقوق. لا اعتماد دوري وقتي غير مضبوط: تُدار النتائج المرجعية بنسخ وتوقيت بدل الاستدعاء الدائري.

## 3. ترابط الهدف والقيمة والوظيفة والقدرة والرافعة

```text
Business / Practice / Offering / Goal Revision
                 │ asks
                 ▼
Value (product promise; not runtime authority)
                 │ delivered by [many-to-many]
                 ▼
Domain Use Case / Function ──consumes──> Domain Capability ──uses──> Method
      │                                │                       │
      │                                └─qualified evidence───┘ + Validator
      │                                         │
      └──── findings / alternatives / missing proof / abstention
                       │
             [Decision only when needed]
                       │
           Authorized/eligible intervention ───> Execution receipt
                       │
                Accepted Outcome ───> Evaluation (bounded learning)

Lever = typed association to capability/intervention/outcome;
        never automatic owner, permission, universal execution dependency.
```

أشكال العلاقات الأربع الأساسية ليست مترادفة: `DATA_DEPENDENCY` = الاستهلاك المؤهل لمعلومة؛ `EXECUTION_DEPENDENCY` = شرط تشغيل؛ `POTENTIAL_INFLUENCE` = فرضية تأثير تحتاج اختبارًا؛ `VERIFIED_CAUSALITY` = علاقة سببية مثبتة وفق تصميم مناسب. وقد نحتاج `RESOURCE_CONFLICT` عند تنازع ميزانية أو مخزون أو موظف؛ لا تختزل جميعها في `depends_on=true` أو Graph عام.

**البرمجة لا تفرض هذا الرسم كسلسلة تمر بها كل وظيفة.** قد تقدم قدرة معلومات فقط، أو تدعم خطوة يدوية، أو تمتنع، وقد تستهلك نتائج متخصصة دون قضية Commercial Case شاملة. يسجل سياق القرار المؤثر حين يوجد قرار أو خطة مؤثرة، ولا تُخلق سجلات وهمية عند كل قراءة بسيطة.

**مرجع النتيجة المؤهلة.** عند عبور نتيجة بين المجالات يعرّف مالكها نوعها وإصدار عقدها ومرجع نسختها، ويقدّم دلالة المقدار والفترة والنطاق والتغطية والمنهج وعدم اليقين حسب نوعها. يحدّد المستهلك النشاط والممارسة والعرض والهدف وإصداراتها ذات الصلة والسوق والفترة والغرض والعملية والمستلم. تؤهل واجهات المالك المراجع والحق الحالي، ويثبت مالك حالة الاستعمال قاعدة التوافق وإصدارها. الاختلاف المادي في الوحدات أو الموضوع أو مجال الانطباق يحتاج تحويلًا مؤهلًا أو امتناعًا مفسّرًا.

**الحفظ وإعادة التأهيل.** يربط القرار المركب المحفوظ إصدارات السياق والمدخلات والتبعيات المادية وقاعدة التوافق والأسباب، بأقل حمولة تسمح بها الحقوق. تُعاد أهلية الاعتماديات عند الحفظ وبعد انتظار مؤثر وعند الاستعمال المؤجل. التصحيح أو السحب يعيدان تأهيل المعتمد عليه، وتُطبَّق سياسة الاحتفاظ والإخفاء في العرض التاريخي. يُستخدم حد المواد القائم حيث يلزم حق استعمال مصدر. ترخيص العرض لا يجيز التركيب أو النقل.

**الأثر والنتيجة.** التفويض محدد بالمقصد والعملية والنطاق والمدة. تثبت نقطة قبول الإحالة المحلية وترتيبها مع السحب، وتُربط بصمة الحمولة بمعرّف أمر ثابت. فقد الرد يؤدي إلى حالة مجهولة ومصالحة عند موائم المزود؛ يتوقف الإرسال عند غياب ضمان التكرار الآمن. مالك واقعة الحجز أو البيع أو التحصيل يقرر معناها ونسخ تصحيحها، ويثبت التقييم تعريف القبول ونافذة النضج وخط المقارنة وحدود الإثبات.

**التأسيس عند أول استعمال مركب.** يثبت عقد المرجع والتوافق قبل نشر أول قرار مركب محفوظ، باختبار مخرجين مختلفين من مالكين فعليين، وتغير سياق وسحب حق مع الحفاظ على الاستعمال الذي بقي مؤهلًا. وظائف القراءة والتشخيص المحلية تستعمل عقود ملاكها الحالية. حالة الاستعمال تملك قاعدة التركيب، وتبقى حمولة النتيجة عند مالكها. تخدم إسقاطات العلاقات عند الحاجة الاستعلام عن حواف ذات أنواع معروفة ومنشأ محدد.

## 4. العقد الذي يحوّل «قيمة» إلى عمل قابل للتنفيذ

كل وظيفة تستحق التنفيذ تُعرَّف في بطاقة قصيرة **Value Delivery Specification**؛ هذه هي الشروط المهمة، وليست التزامًا بإنشاء جدول باسمها:

| البند | المطلوب | علامة عدم الاكتمال |
| --- | --- | --- |
| Value / Goal | مستخدم مستفيد، سؤال، نتيجة مرغوبة أو قرار يتحسن، نطاق وزمن | قيمة بلا مستفيد أو معنى نتيجة |
| Business Context | عرض/Practice وسوق وقيود القدرة والتكلفة والحقوق | لا نعرف لمن ينطبق التقييم |
| Knowledge Requirements | الأدلة اللازمة لكل فرضية وقبولها وفترة صلاحيتها | مصدر مفقود أو حق غير مؤهل |
| Evidence Acquisition | **من أين نحصل على الدليل؟** تصريح، سجل مملوك، مزود مرخص، مصدر عام، مقابلة/تجربة؛ تكلفة وتغطية | اسم مصدر افتراضي أو API لا يتيح المعلومة |
| Capabilities & Methods | نتائج تخصصية ومدققات وحدود تفسير، بدائل منهجية مناسبة | خوارزمية بلا أساس اختبار أو تحيز/دقة معلومة |
| Practical Route | **كيف نوظف المعرفة؟** خيار، إجراء بشري أو آلي، تواصل مأذون، تعديل عرض أو سعة؛ أهلية فنية/مالية | وصول نظري بلا طريق فعل قابل للاختبار |
| Alternative | عدم التدخل، إجراء أبسط، تحسين آخر، أو طلب المعلومة الأعلى قيمة | «إعلان إضافي» افتراضي بلا مقارنة |
| Authorization & Entitlement | حق القراءة، تفويض العملية، ترخيص المصدر، أهلية المزود، استحقاق إن لزم | أي حاجز مجهول لعملية مشروطة = HOLD |

**درجات المنفعة:** `INSIGHT_DELIVERED` قراءة أو تقييم صحيح ضمن حدوده، `ACTIONABLE_OPTION` بديل مؤهل، `ACTION_EXECUTED` فعل مؤكد، `OUTCOME_OBSERVED` نتيجة ناضجة، `IMPACT_EVALUATED` تقييم أثر بحسب الدليل. لا يجوز رفع الأولى إلى الخامسة آليًا. عدم توافر النتيجة يعني `VERIFICATION_NOT_AVAILABLE`، وليس أن القيمة «لم تحدث» أو أنها «تحققت».

**مصادر الإثبات ثلاثة:** (أ) مصدر المعلومة وحق استخدامها؛ (ب) إثبات صلاحية الوسيلة وتأهيلها؛ (ج) مصدر واقعة النتيجة. عند غياب أحدها، تتوقف المطالبة عند المستوى المثبت وتحدد السؤال التالي، لا تختلق مصدرًا أو حساب عميل أو موافقة أو أثرًا سببيًا.

| ما الطرق التي قد تصل إلى الطلب؟ | DemandReach يستهلك الأدلة والسعة والتغطية والجدوى | خيارات: بحث، شراكة، موزع، محتوى، فعالية، إعلان، بيع مؤسسي، غيرها |
| هل تفعيل الطريق متاح ومأذون؟ | Sources + مزود/اتفاق + Execution + حقوق/امتثال | READY/UNKNOWN/BLOCKED/HUMAN_HANDOFF؛ تختلف إمكانات كل مزود |
| هل أنتج الطريق نتيجة مجدية؟ | Outcome owner + BusinessEconomics + Evaluation | عقود/مبيعات/حجوزات/فرص مؤهلة مقابل التكلفة؛ لا دليل سببية تلقائيًا |

**عقد وصول متخصص (دلاليًا لا جدول JSON عام):** `OfferingRef+Version`, `GoalRef+Version`, `BuyerContext` مع منشأ فرضية/دليل، `QualifiedDemandRefs`, `RouteCandidates`, `RouteEligibility` حسب البلد والمزود والحق والقدرة والسعة والتكلفة، `Choice/Abstention/NextQuestion`, `VerificationPlan`. يحافظ المنسق على مصادر الأدلة ونسخها ولا ينسخها، ويترجم موائم المزود فقط الخصائص التي يدعمها رسميًا عند وقت التفعيل.

**فصل فئات البيع:** النشاط قد يبيع لأفراد أو شركات أو متاجر أو طلاب أو موزعين أو مؤسسات متعددة الأطراف، وقد يبيع لأكثر من فئة في العرض نفسه. لا نخلط «فئة مشترٍ» بـ«شخص طبيعي قابل للاستهداف»، ولا نستنتج حساب الموظف أو المدير أو نراسل أشخاصًا اعتمادًا على معلومات غير مرخصة. تُراعى القوانين والحقوق وشروط المنصات وحماية القُصّر. قد يكون الطريق الأجدى **موزعًا أو تسعيرًا أفضل أو قدرة وفاء أعلى** لا استهدافًا رقميًا.

**العائلات البحثية الـ34 ليست كلها وصولًا جديدًا:** A التقاط طلب قائم، B تكوين معرفة وثقة، C بيع مؤسسي/قنوات، D علاقة مع عملاء حاليين، E إزالة عوائق التحويل بعد الوصول. عائلة E تعيش وظيفيًا لدى `OfferStrategy/SalesConversion/FulfillmentFit` حسب المالك، ولا نحبسها في `DemandReach`. الفهرس المختصر في الملحق هـ.

## 9. عقود التنفيذ في Laravel / PostgreSQL / Vue

### 9.1 هيكل مبدئي — مسؤوليات، لا أمر بإنشاء مجلدات فارغة

```text
app/
  Business/                   # هوية النشاط والممارسة والعرض والهدف
  Foundation/Business/        # سلطات Business وعقود القراءة المؤهلة الموجودة
  Sources/                    # اتصال المصدر وإتاحته وحقوقه
  MarketKnowledge/            # أدلة ومناهج السوق ومدققاتها
  Commercial/
    [MarketOpportunity]/      # عند أول مستهلك فعلي
    [DemandReach]/             # تخطيط طرق الوصول وشروط التأهيل
    [OfferStrategy]/
    [AdvertisingPerformance]/
    [SalesConversion]/
    [FulfillmentFit]/
    [BusinessEconomics]/
    [CustomerRetention]/
    [CommercialDecisions]/
  Security/                   # سلطة وأمن قائم لا نظام بديل
  Providers/                  # موائمات مزودين بمستويات قدرات واضحة
resources/js/                 # واجهة تستهلك Use Cases، لا مالكة للمعنى
contracts/                    # عقود عامة منشورة فقط عند وجود مستهلك
sql / migrations/             # محفوظة وفق مسارات المصدر المعتمدة
```

**عند إضافة وظيفة:** (1) توثيق سؤالها وقيمة النتيجة؛ (2) مالك المجال وعقد الاستهلاك؛ (3) أدلة ومدققات وحقوق؛ (4) حالات `UNKNOWN/BLOCKED/INCONCLUSIVE` الصريحة؛ (5) تنفيذ أو خطوة يدوية أو امتناع؛ (6) نتيجة/إيصال أو بيان عدم القدرة على التحقق؛ (7) اختبارات سلوك/حقوق/توافق. تُثبّت حدود المعنى والحقوق والتوافق قبل نشر أول مستهلك يحفظ اعتمادًا عليها. تُستخلص آليات إعادة الاستخدام الأوسع من استعمالات فعلية.

### 9.2 شكل العقد عند الحد — مثال تصور، وليس API صالحًا للنشر

```php
// PSEUDOCODE: maintain these semantic boundaries without inventing
// a universal interface, storage table, or alternate authority model.
function assessReach(AuthorizedContext $ctx, OfferingRef $offer, GoalRef $goal): ReachAssessment {
    $facts    = businessOwner()->readQualifiedContext($ctx, $offer, $goal);
    $evidence = knowledgeOwners()->readForPurpose($ctx, 'reach_assessment', $facts);
    $options  = reachCapability()->assess($facts, $evidence);
    $verified = independentValidator()->validate($options, $facts, $evidence);
    return reachUseCase()->presentEligibleOptionsOrMissingEvidence($verified);
}
// An actual external command would run in a separate authorization
// boundary with fresh rights, entitlement, provider eligibility and receipt.
```

**قواعد الدقة:** لغة العقد تخصصية ومحددة المجال؛ لا اجتهاد لحساب حقوق البيانات من الـDTO؛ لا SQL عبر وحدات مملوكة إلا عبر واجهات مؤهلة؛ لا مدقق ينقل إلى داخل تنفيذ المنهج إذا كان بذلك سيلغي التحقق المستقل. تستند عمليات القراءة والكتابة الأمنية إلى سلطات Business/RLS الموجودة، وتؤخذ لقطة مرجعية مصرح بها من نسخة هدف وممارسة ودليل عند القرار؛ لا إعادة كتابة للتاريخ عند التصحيح.

### 9.3 حالات الفشل والسلطة الفعلية

| الحد | شرط السلامة |
| --- | --- |
| Business / Agency | عزل النشاط والتفويض والموظف، وسحب الصلاحية يمنع استعمالًا جديدًا غير مصرح |
| Qualified knowledge | غرض وحقوق وسياق ونطاق وتغطية وإصدار وصلاحية؛ تصحيح/سحب يعيدان تأهيل المستهلك |
| Capability / Method | تسجيل محكوم برمجيًا؛ مدخل صالح، مخرجات محددة، مدقق متخصص مستقل عندما تلزم صحة حسابية/دلالية |
| Decision | بدائل مقبولة ومجهولات واضحة، مع مرجع هدف/سياق/منهج/أدلة وإصداراتها |
| External action | تفويض جديد وقت التنفيذ، command_id ثابت، مخارج `UNKNOWN` ومصالحة مزود؛ لا إرسال مكرر بسبب ضياع الرد |
| Product feature | استحقاق منفصل عن حق البيانات والتفويض؛ الغائب `HOLD` للوظائف المشروطة لا ALLOW |
| AI / Automation | أداة محدودة الحق والتكلفة والمدخل والمخرج؛ مخرج النموذج لا يوافق بنفسه على إجراء |
| Outcomes | البيع/الحجز/التحصيل مثبت من مالكه؛ الإسناد ≠ الإضافية؛ تصحيح لاحق لا يمحو ما سُجل تاريخيًا |

### 9.4 تعليمات تصميم التشغيل

- **التخزين:** PostgreSQL وعقود SQL الحالية ومفاتيح إصدار/معاملة، دون Graph أو قاعدة ثانية مسبقًا؛ توضع قيود Unique/FK/Check وRLS عند ملكية الجدول. لا نغير هجرات تاريخية منشورة دون خطة انتقال متوافقة.
- **التكاملات:** موائم مزود وفق قدرات محددة (`read`, `report`, `create`, `edit`, `verify`) وليس حالة «متصل» العامة؛ المسار البشري أيضًا خيار عملي يحتاج معيار متابعة نتيجة ولا يُعلن API-ready.
- **الطوابير:** لا إطلاق أثر اعتمادًا على معاملات غير ملتزمة؛ لا ثقة في إكمال أداة دون إيصال أو إعادة قراءة/مصالحة. إعادة المحاولة تحترم المعرف الفريد والسلطة الحالية.
- **الواجهة:** «السوق والعملاء» يعرض قيمة فهم المشتري والوصول دون عشرات حقول الاستهداف؛ «المبيعات والتحويل» يعرض وظائف الاستفسارات والتأهيل والبيع؛ «النتائج والعائد» يستهلك نتيجة مؤهلة؛ «القرارات والتحسين» يعرض البدائل/الأثر. إخفاء عنصر واجهة لا يمثل رفضًا أمنيًا.
- **Zero-Setup:** يبدأ من بيانات نشاط قليلة وهدف معقول وتوصية مشروطة أو سؤال عالِ القيمة؛ لا أرقام إعلانية أو «ذكاء سوق» بلا مصدر.

### 9.5 هندسة القدرات وحدود التركيب

**عقد القدرة عند حد الاستهلاك** يملك مجال القدرة معنى السؤال ومقياس النتيجة واختيار المنهج من الإصدارات المدعومة بحسب السؤال والمدخلات المؤهلة. يقرّر المدقق التخصصي المستقل صلاحية النتيجة عندما يتطلب الحكم تحققًا دلاليًا أو حسابيًا. يصرّح العقد بأسباب القبول والامتناع والتغطية وعدم اليقين، ويميّز عدم الانطباق عن غياب الدليل أو تعارضه أو منع استعماله. يبقى المخرج المؤقت نوعًا محليًا. إذا نُشر للاستعمال الخارجي يُثبّت نوعه وإصداره ومرجع نسخته قبل نشر مستهلكه. إذا دخل قرارًا محفوظًا يثبّت المستهلك استعماله المحدد وتبعياته ومبرره.

**مخطط المكونات والاعتماديات**

~~~text
Vue / API → حالة الاستعمال → واجهات ملاك السياق والنتائج
مجال القدرة → اختيار منهج → مدقق مستقل → نشر لدى المالك
واجهة المالك → تأهيل المصدر والنطاق والغرض والحقول والعملية
مالك القرار → مراجع المالكين وقاعدة التوافق وإصدارها
مالك التنفيذ → بوابة سلطة مستقلة → موائم العملية والمزود
مالك التقييم → مالك الواقعة وسجل التدخل وتعريف القبول
~~~

**تدفق الدليل والنتيجة**

~~~text
مصدر → قبول النسخة → تأهيل الحقول والغرض → معالجة ومدقق
      → نشر نتيجة بنسبها → قراءة مؤهلة للعملية المطلوبة
      → تركيب وفق دلالة النتائج → تشخيص أو قرار أو امتناع
تصحيح أو سحب → إعادة التأهيل عند المالك → فحص التبعيات المتأثرة
واقعة من مالكها → ربط بتدخل → نضج وتصحيح → إصدار تقييم جديد
~~~

**تسلسل قرار مركّب وتغير الحقوق**

~~~text
1. الوظيفة تثبّت السؤال والسياق والإصدار والعملية المطلوبة.
2. الملاك يؤهّلون كل مخرج وتبعياته. حق display لا يجيز combine أو reuse.
3. الوظيفة تقارن الموضوع والوحدة والزمن والتغطية والقيود بمنهجها المعلن.
4. قبل حفظ قرار قابل للاعتماد، تعيد بوابة الحفظ فحص الإصدارات والحقوق
   المادية داخل حد المعاملة بما ينسجم مع ترتيب أقفال المالكين.
5. سحب سابق للقبول يمنع إصدار قرار قابل للاستعمال. سحب بعد الحفظ
   يمنع الاستعمال اللاحق المتأثر. عرض التاريخ نفسه يخضع لحقوقه.
6. أمر مؤجل يعيد التأهيل عند حد الإحالة، ثم يصالح أي أثر خرج إلى المزود.
~~~

**ربط التقييم المحفوظ بحقوله.** حق إعادة عرض نتيجة المصدر وحدها لا يجيز كشف حكم محفوظ استند أيضًا إلى إسقاط مقيّد. يتحقق مالك التقييم من أن القراءة الحالية تجيز الأساس المربوط بالحكم قبل إرجاعه. إذا تغيّر الحق يستطيع المستخدم تقديم طلب تقييم جديد تحت حقوقه الحالية. يحتفظ السجل بالمعنى الأصلي ضمن سياسة الوصول والاحتفاظ.

**نقاط إدخال القدرات المستقبلية.** المنهج أو الموائم أو المنسق المحدود يستقبل حقولًا مؤهلة وغرضًا وميزانية وإصدارًا. AI يخضع لمدقق المجال وتُعامل مخرجاته وتعليمات المواد المسترجعة كبيانات. هوية الأمر وحدود التفويض وحالة الأثر المجهول شروط قبل أول كتابة خارجية. اعتماد أثر تجاري يتطلب تعريف نتيجة ونضجًا وخط مقارنة وإذن الاحتفاظ أو التعلم. الحصص والاستحقاق وأهلية المزود وحقوق البيانات وسلطة الفعل أبعاد مستقلة.

**توقيت التأسيس.** حد المرجع وتأهيل الاستعمال جزء من عقد كل نتيجة منشورة. حفظ القرار المركب جزء من أول حالة استعمال فعلية تحتاج الحفظ. يمكن بناء القدرات التخصصية على عقود ملاكها الحالية مع هذه الشروط. دليل القراءة متعددة المواد وإعادة عرض التقييم الحالي لا يثبت معاملة حفظ قرار مركّب أو إحالة مؤجلة.

## 10. الترتيب البرمجي الحاسم — من الوثيقة إلى إثبات فعلي

| التتابع | العمل التنفيذي | شرط الإغلاق | تجنّب |
| --- | --- | --- | --- |
| **A — Version & Source** | تحقق من مسار Codex وGit HEAD وحالة العمل المحلية؛ طابق النسخ المنشورة بالمصدر المرفق؛ احتفظ بالتعديلات غير المنشورة | سجل النسخة/التغييرات والمستهلكين الحقيقيين | لا شجرة/Commit/PR أو مسح جديد بلا سبب |
| **B — Ownership Reconciliation** | عرّف مالك كل معنى/حق/نتيجة موجود، وقارن الكود بهذا المرجع؛ عالج خطأ تصنيفي أو ازدواجًا ماديًا مثبتًا فقط | خريطة `REUSE / REFACTOR / REQUIRED / DEFER / REJECT` بمراجع ملفات | لا نقل كود لغرض المطابقة الشكلية |
| **C — Critical seams** | عالج حدود القراءة والمؤشرات والقدرات والمدقق/القرار عند أول مستهلك حقيقي | اختبارات إثبات اقتران مفكوك، وعزل وإصدار وحالات فشل | لا واجهات عامة لا مستهلك لها |
| **D — Real vertical slice** | اختر قدرة تقدم قيمة فعلية بالأدلة والحقوق ووسيلة توظيف ونتيجة/نقص معلن؛ نفذها في مالكها | من سياق Business إلى نتيجة مؤهلة/خطوة عملية أو امتناع صحيح | لا اختيار «الوصول» تلقائيًا لمجرد كثرة دراسة وصوله |
| **E — Cross-domain proof** | وظيفة ثانية في مجال آخر تستهلك دليلًا أو قدرة مشتركة من الأولى دون نسخ أو سلطة إضافية | تحقق التصحيح والسحب، النسخ، تغيير الهدف، عدم تغير غير المعنيين | لا محرك Composition عالمي |
| **F — Closure** | تقاعد تعليمات وثائق متعارضة بعد تتبع مراجعها، وتقرير ما نُفذ وما أُجّل وحدود الاختبار | `VERIFIED_WITH_SCOPE` أو `SPECIFIC_BLOCKER` أو `VERIFICATION_INCOMPLETE` | لا نجاح Foundation مبهم ولا فتح جولة تأسيس بلا نهاية |

**اختيار أول وظيفة ليس تصويتًا على اسم رافعة:** درجة الملاءمة = (قيمة المستخدم المحتملة + حقوق/تغطية الدليل + وسيلة التفعيل الواقعية + إمكانية القياس + كلفة التنفيذ والمخاطر + وضوح البديل). لا نحولها إلى «نقاط» دقيقة بلا معايرة؛ استخدم مقارنة مكتوبة قابلة للمراجعة، وجرّب أولًا ما يملك أدلة يمكن الوصول إليها بحق.

**نطاق الصلاحيات عند إسناد التنفيذ:** الفحص والتعديل والاختبارات المحلية؛ لا Commit أو Push أو PR أو دمج أو نشر أو بيانات إنتاجية دون تفويض صريح. لا تشغيل Foundation محلي شامل تلقائيًا؛ التشغيل الموجه ثم بوابات CI بحسب أثر التغيير، و`PENDING` للبوابات التي لم تتوفر.

## 11. حالات القبول التي تميز بنية صحيحة عن بنية شكلية

| سيناريو إثبات | السلوك المطلوب / علامة الفشل |
| --- | --- |
| قدرة جديدة تستخدم نتيجة مجال آخر | عقد مالك واحد، لا نسخ جدول أو نتيجة أو استخدام SDK داخلي بلا تفويض |
| منهج جديد لنتيجة سوقية | مدقق متخصص مستقل، تسجيل محكوم، لا كسر نتائج الإصدارات القديمة |
| قدرة في قيمتين ورافعتين | لا توأمان منفصلان للقدرة ولا إعادة كتابة التاريخ بسبب إعادة التصنيف |
| دليل واحد يستهلكه تحليلان | أهلية مستقلة لكل قراءة؛ التصحيح/السحب يوقف استعمالًا لاحقًا غير مؤهل |
| تمييز فئات مشتري وشركة وشخص | تصريح مقابل دليل سوق مقابل هوية وحقوق تواصل؛ لا جمهور فردي مختلق |
| فرصة سوق خارج تغطية الخدمة | نتيجتها غير قابلة للتفعيل، ولو مؤشرات الاهتمام مرتفعة |
| قناة مزود غير قادرة على الاستهداف المراد | `BLOCKED/UNKNOWN` دون إعداد unsupported؛ بديل أو سؤال لا تفعيل كاذب |
| عرض أو هدف تغير بعد التقييم | القرار القديم يُراجع بإصدار سياقه، ولا يُزوّر؛ المفتوح يعاد تأهيله |
| دفع/رسالة/إنفاق بعد فقد رد المزود | `UNKNOWN` ثم مصالحة؛ لا retry أعمى يكرر الأثر |
| خفض الاشتراك أو سحب تفويض وكالة | لا تُحذف بيانات النشاط، ويُمنع استعمال الحق المسحوب/الميزة غير المستحقة |
| AI خرج بتوصية أو محتوى ضار/غير مؤهل | لا يصبح حقيقة أو أمرًا؛ يراجع الحد التخصصي والحقوق والتكلفة |
| إشارات تحويل ونتائج تجارية | لا تُساوى API success بمبيعات أو إسناد منصة بأثر إضافي |
| تحليل فقد الاستفسارات | موضعه المقدم ضمن `SalesConversion` مع حفظ مالك الإفادة الحالي |
| Zero-Setup بنشاط بلا حساب إعلاني | سؤال/منفعة مدعومة أو حالة نقص صادقة، لا لوحة بأرقام مزيفة |

**الأدلة:** اختبار PHP/SQL لـRLS/العزل/الحقوق/التزامن، واختبار TypeScript/API للعقود، وسيناريو متصفح للوظيفتين كما يراهما المعلن، واختبار تغير/سحب يميز الكود المعدّل. تُوثّق نسخة الكود والأمر والنتيجة؛ Mock فقط لا يكفي لإثبات مصدر/SQL/مزود فعلي.

## 12. التعامل مع وثائق المستودع القديمة وتصحيح الكود

- **المراجعة ليست ترحيلًا آليًا لوثائق «FINAL»**: افحص `AGENTS.md` وعقود API و`docs/` وسجلات التنفيذ ومراجع الاختبارات. صنّف `CURRENT_SECURITY_CONTRACT`, `CURRENT_DOMAIN_CONTRACT`, `HISTORICAL_EVIDENCE`, `SUPERSEDED_INSTRUCTION`, `CONFLICTING_OBSOLETE`, `REDUNDANT`.
- ما يثبت أنه ضمان أمني/حقوق/عزل/تاريخ معتمد يبقى نافذًا حتى إذا تغير الاسم أو السياق. أما تعليمات فرض شجرة عمل/خطة/مجال أو معمارية متقادمة فتُصحح أو يُزال إلزامها بعد تتبع مستهلكيها وتأثير ذلك على الاختبارات.
- **الكود الحالي لا يحدد تصميم المستقبل:** يجوز تعديل وظيفة أو فصلها أو إعادة موضعتها إذا ثبتت مصلحة المعمارية وعُرفت كلفة الاستبدال والتوافق. مثال: إفادات الاستفسارات تبقى دليلًا مملوكًا لجهتها الحالية، لكن وظيفتها وتجربتها وعلاقتها بقيمة التحويل تقع في `SalesConversion`؛ لا CRM آخر ولا حذف تاريخ.
- لا يُنقل مصدر حقيقة أو تفويض إلى Domain آخر لأن اسمًا في الخطة تغيّر؛ القرار بحاجة إلى أثر مدقق على SQL وAPI والتصحيحات والحقوق والمستهلكين.

## 14. ماذا تعني «نهائية» وما الذي لا ندّعيه؟

نهائية هذا المرجع تعني **حسم التصنيف والملكية وآلية إنشاء الوظيفة وإثبات القيمة وحدود الربط والاختبارات**. لا تعني اكتمال 104 قدرات، أو توافر 34 قناة، أو جاهزية 37 هدفًا في الواجهة، أو تحقق جميع العلاقات البحثية، أو وجود خوارزمية تمنح «أفضل قرار» دائمًا.

**قرارات مفتوحة عمدًا حتى وجود دليل فعلي:** أول وظيفة ذات أفضل اقتصاديات، المصدر المرخص الذي يملك بياناتها، شكل أول عقد اشتراك مدفوع وتسعيره، النموذج/الخوارزمية الأنسب لكل مجال، مستوى التفعيل المتاح عند كل مزود، والنتائج التجريبية التي تثبت الأثر. هذا ليس نقصًا في التنظيم؛ هو منع الالتزام بتصميم لم تُثبت مستلزماته.

**نتيجة العمل البرمجي المطلوبة:** `READY_FOR_TARGETED_IMPLEMENTATION` مع عقود ومستهلكين معلومين، أو `SPECIFIC_CAPABILITY_BLOCKER` بمالك وسبب ومصدر/حق/اختبار ناقص. وبعد التنفيذ: `VERIFIED_WITH_SCOPE` فقط لما اجتاز الأدلة. لا مراجعات دائرية ولا شهادات شمول مستقبلي غير قابلة للإثبات.
