Service create/rotate JSON replies are emitted only behind the existing web middleware: CSRF/origin admission, signed `AdmitIdentityDocument`, internal/current authentication, explicit `service.manage` and Fresh Authentication. `IdentityDocument.admit` verifies the existing receipt against lineage, epoch, principal, boundary, credential and generation before the controller. These owners are unchanged. Ordinary service reads have no credential or `newCredential`; the issuer still stores only SHA-256 and audits in its original authority transaction. Native legacy command redirect/flash representation is retained, but ordinary SPA reads do not deliver that flash. The migrated UI uses the actual one-time JSON command response, never a flash readback.

The credential is held only in the receiving component, not shared resource state, query cache, bootstrap, history, browser storage or telemetry. Dismissal, pagehide, visibility loss, unmount and identity closure release presentation references. This is not a claim of physical JavaScript memory erasure. Lost create/rotate acknowledgement remains unknown, warns that rotation may already have invalidated the old value, cannot recover the secret and cannot replay automatically. Explicit current-state review is not acknowledgement of the original delivery. A fresh native document does not resurrect component secrets or old acknowledgements.

Known command acknowledgement is separate from failed list refresh. Authority denial closes private presentation; serial/identity ownership checks reject old reads and navigation cancellation cannot publish a late rotation response. No SessionAuthority, StaffAuthority, GrantAuthority, ServiceIdentityAuthority, WorkspaceContext, SQL/RLS, N1, middleware order, route authorization or security timeout implementation changed.
