# حزمة مواءمة ملاحة المعلن وموضع BF03

**المعرّف:** `BA-ADVERTISER-UX-C01 / 2026-11-03`، تابع لـ[مرجع التجربة المثبت](ADVERTISER_UX_BASELINE.md) و[البرنامج](PROGRAM.md). **تحديث المتابعة:** نُفذ سطح Vue المحلي بعد طلبات المالك المتتابعة لإصلاح التطبيق الفعلي ورفضه التصميم واللغة الحالية وتأكيد المقاسات المدمجة. يغطي التنفيذ الغلاف وقائمة/إنشاء/داخل النشاط والمصادر وحقوق البيانات وموضع BF03؛ لا SQL/API/صلاحيات جديدة. [سجل التنفيذ](IMPLEMENTATION_PROGRESS.md) يفصل التحقق الحالي وحدوده. وصف «المواصفة المقترحة/لم يبدأ» في نهاية هذه الوثيقة يحفظ نهاية مرحلة إعدادها السابقة، ولا يصف هذه المتابعة.

## 1. المشكلة والنتيجة المطلوبة

الواجهة القائمة توزع الهوية وروابط Business وتنقل العمل على طبقات، وتقدم BF03 كوجهة رئيسية داخل النشاط رغم أنه حفظ إفادات مجمعة لا تتبعًا تجاريًا. النموذج الأخير يوضح خريطة المنتج، لكنه احتوى سجلات استفسارات فردية وتجريبًا محليًا لا يمثل عقود التطبيق. تعالج الحزمة التنظيم والعرض المؤهل، دون صناعة الوظائف الناقصة.

النتيجة: غلاف معلن مهني بأسماء الأقسام السبعة والمساندين، تمييز صريح بين الوجهات المتاحة والمستهدفة، ووصول واضح إلى «النشاط والفريق والإعدادات ← البيانات والإفادات ← إفادات الاستفسارات». تبقى كل قراءة وأمر عند مالكها وسلطتها الحالية. لا تختفي منفعة عدد المجموعة وقناتها وفترتها وتغطيتها خلف عرض تقني، ولا تُعرض كعملاء أو بيع.

## 2. ملاك الحدود والثوابت المنطبقة

- Foundation Business/BusinessScope يملك مورد النشاط وتأهيله؛ `BusinessSurface` يستهلكه، و`BusinessWorkspace` ينسق العرض. BF03 يملك حفظ الإفادة وقراءتها؛ لا تنشأ سلطة نقل بيانات باسم غلاف الواجهة.
- `spa/router.ts` و`presentation.ts` و`transport.ts` يملكون قبول الوجهة والهوية والإخفاء والتذاكر. يعاد استعمالهم، ولا يتجاوزهم handler لملاحة جديدة.
- `INV-001/002`: لا اعتماد مزود داخل Core، ولا حساب إعلان/CRM/هدف شرطًا عامًا. `INV-003`: النقص يعطل التابع الحقيقي فقط. `INV-004/005`: العزل وملكية الحقيقة وunknown/zero والتاريخ. `INV-007`: التنقل أو قراءة رقم لا يجيزان تنفيذًا أو تحليلًا جديدًا.
- Shared Appearance/Brand/locale owners يبقون كما في DESIGN.md وUX-CONTRACT.md؛ لا مكتبة تصميم أو إعداد لون أو theme store ثانية.

## 3. ملاحة الإنتاج: المتاح مقابل المستهدف

الخريطة المستهدفة ثابتة، لكن اعتمادها لا يفوض إنشاء صفحات نشطة لخدمات غير منفذة. يُسجّل وضع كل مدخل في manifest عرض محدود؛ **هذا بيان مواضع وإتاحة عرض، لا سجل قدرات أو سلطة جديدًا**. الوجهة غير المنفذة لا تكون رابطًا إلى صفحة فارغة؛ تظهر بحالة مفهومة «ضمن التصور — غير متاحة بعد» مع شرح قابل للقراءة/التركيز، أو كعنصر معلومات غير تفاعلي في موضعها. لا tooltip بالفأرة وحدها ولا شارة «قريبًا» بوعد زمني.

| المدخل | ما يدخل الحزمة فعليًا | ما يبقى خارجها |
|---|---|---|
| الرئيسية | نظرة نشاط مؤهلة: سياق متاح، أفعال قائمة، حدود واضحة؛ لا ترتيب ذكاء أو KPI مخترع | توصيات ومراقبة تجارية جديدة |
| السوق والعملاء | تثبيت الاسم/الموضع وحالته المستهدفة؛ إحالة معلومة إلى حدود الخدمة عند الحاجة دون رحلة منتج مزيفة | تحويل D3 endpoints إلى اكتشاف مشتري أو منافسة أو بحث حي |
| العروض والخطة | استضافة **المحرر القائم فقط** للنية/الأسواق المعلنة/التفضيلات عند rights الحالية، بتسمية وظيفة محلية واضحة | محرر منتجات عام أو محرك خطة وصول/رسائل جديد |
| الإعلانات | حفظ مدخل إلى أفعال Sources/provider readings القائمة عندما يوجد Workspace مؤهل؛ عند غيابه توضيح السياق المطلوب واختيار مساحة مخولة عبر المسار القائم | افتراض أن Business=Workspace، أو إطلاق targeting/budget writes |
| المبيعات والتحويل | موضع مستهدف معلوم الحالة؛ رابط سياقي إلى BF03 إذا انطبق حقه، دون تتبع تشغيلي أو سجل أفراد | CRM/صفقات/حجوزات/استفسارات فردية/إرسال |
| النتائج والعائد | موضع مستهدف وحالة عدم توفر الأدلة؛ إن وُجد رابط إلى إفادة يكون رابط قراءة المجموعة فقط، لا لوحة نتائج | تجميع أفواج أو CPL/ربح/إسناد/رسم نتائج مصطنع |
| القرارات والتحسين | موضع مستهدف معلوم الحالة؛ لا نقل حالات JavaScript التجريبية | محرك توصية أو موافقة/فعل/قياس أثر جديد |
| المصادر والتكاملات | روابط وأفعال المصادر/SourceRights/DataBoundaries القائمة وفق سياق كل مورد وحقوقه | منح ضمني من ظهور القائمة أو إنشاء خدمات مزامنة |
| النشاط والفريق والإعدادات | معلومات النشاط/تعاون/تفويض/استعمال بيانات/الغرض/التاريخ عند أصحابها؛ إدارة BF03 تحت البيانات والإفادات؛ الحساب إلى سطحه القائم | فوترة/اشتراكات/حصص جديدة أو إعادة تصميم الإدارة المركزية |

إذا كان إظهار الخريطة كلها في أول زيارة يثقل المهمة، يجوز طي مجموعات الإتاحة المستقبلية **مع إبقاء الأسماء والمواضع قابلة للفهم والاكتشاف**؛ لا اختراع قائمة مختلفة لكل قطاع. الأعمال المتاحة لا تتطلب المرور بمحتوى تصوري أولًا.

## 5. الانتقال وحفظ السلوك

- `/businesses`, `/businesses/new`, `/businesses/:business?access=...` تبقى عند نفس admission؛ لا تخزين grant في localStorage أو تحويل query إلى حق.
- قيمة العرض المحلية القديمة `inquiries` تُترجم إلى `settings/data/inquiry-evidence`، و`direction` إلى الوظيفة المحلية المقابلة داخل الخطة، دون تغيير هوية الأمر أو استدعاء تصحيح. لم تكن الـsection القديمة عقد URL مستقلًا؛ إذا ظهر رابط خارجي محفوظ يفحص قبل إزالته.
- التنقل المحلي لا ينشئ تحميلًا مزدوجًا أو صلاحية جديدة. `active` الخاص بـInquiryEvidencePanel يجب أن يعني **ظهور وظيفة الإفادات نفسها**، لا مجرد ظهور إعدادات النشاط. إخفاؤها يوقف/يبطل ردود القراءة ويخفي protected collection/history/editor-derived state كما الآن.
- السياق الراجع يحفظ القسم والموضع والتركيز فقط. المسودة غير المرسلة تبقى document-memory داخل المفتاح المؤهل، لا تُعاد كحقيقة ولا تتجاوز requalification. لا remount متكرر يفقد المسودة أو يكرر command، ولا v-show يجعل بيانات مسحوبة متاحة.
- سحب القراءة يخفي المجموعة والتاريخ والقيم المشتقة منهما حتى إن بقي record/correct grant. سحب حق الكتابة يغلق المحرر المتأثر وفق السلوك الحالي ويبقي القراءة المستقلة إن كانت مخولة.
- pending/unknown يحتفظ بنفس command ID والجسم؛ الرجوع أو تغيير القسم لا يعيد الإرسال أو يصنع سجلًا بديلًا. نتيجة الحفظ المؤكدة وفشل إعادة القراءة حالتان مختلفتان. تبديل actor/document/Business يبطل tickets والردود القديمة.
- التواريخ تُعرض مقروءة مع المنطقة/المعنى، مع بقاء القيمة الأصلية في التفاصيل عند الحاجة؛ العرض لا يعيد تفسير period/as-of/cutoff أو يضيف parser مختلفًا. حفظ الوصف ومعيار قبوله وإصداره والتاريخ كاملًا.

## 6. اختبارات قبول سلوكية قبل وصف الحزمة مكتملة

| الحالة/الفعل | النتيجة المرصودة المطلوبة |
|---|---|
| معلن جديد بلا اتصال وبلا غاية | ينشئ/يفتح النشاط ويجد المعلومات والأفعال الفعلية؛ لا أرباح/فرص/طلبات مصطنعة أو اشتراط مزود |
| مستخدم مخول يبحث عن بياناته | يصل من الإعدادات/البيانات والإفادات إلى السجل، ثم يرجع لقائمته ومكانه وتركيزه؛ لا مسار طويل عبر منتج مؤجل |
| قراءة إفادة/صفر/مجهول | يرى العدد والقناة والفترة/التغطية ومعيار القبول، ويفهم أنها إفادة؛ لا صفر ضمني أو عدد أشخاص أو مصدر اكتساب مستنتج |
| تسجيل مجموعة ثم تصحيح ثم تاريخ ثم سحب | يعود إلى الإفادة المناسبة، تحفظ الإصدارات السابقة ومعانيها، لا يتكرر العرض الكامل تلقائيًا لكل التاريخ؛ لا تتحول العملية إلى lead stage |
| مسودة ثم انتقال محلي وعودة | تعود المسودة تحت نفس أصل التصحيح بعد التأهيل الصحيح؛ لا تعيد اعتماد revision أحدث بصمت ولا تعيد إرسال الأمر |
| سحب read/record/correct كل على حدة | يحجب/يغلق ما يعتمد على الحق المسحوب فقط؛ القراءة لا تمنح write، والإعدادات أو sidebar لا تمنح أي حق |
| رد قراءة بطيء ثم تغيير subview/Business/user | لا تظهر صفوف أو تفاصيل أو criterion أو status تخص السياق السابق؛ يختبر تأخير استجابة مقصودًا، لا timeout غامضًا |
| server commit ثم فقد ACK ثم تنقل/عودة | لا أمر بديل أو duplicate؛ exact retry/current qualification كما الحال؛ فقد read لاحق لا يكشف snapshot قديمًا |
| stale correction وتغير resource qualification | رفض مفهوم مع حفظ baseline الصحيح؛ لا overwrite أو تغيير protected contract لتجاوز الحالة |
| رابط قديم/رجوع-تقدم/تبديل النشاط | الوصول نفس server-qualified route؛ الخريطة الجديدة تصحح موضع العرض فقط، no foreign Business content |
| 390/768/1440 × RTL/LTR × نهاري/ليلي | عناوين وأزرار وجداول واضحة، targets موبايل ≥44، لا قص/تداخل/تمرير صفحة أفقي؛ لقطة سياق ولقطة حالة لكل نموذج مهم |
| Keyboard/حوار/Drawer/قائمة محلية | ترتيب تركيز منطقي، ESC وإعادة التركيز، خلفية غير تفاعلية، aria current/labels صحيحة؛ لا faux ARIA tabs |
| حساب/أمان/خروج/locale/إدارة داخلية | تبقى الأسطح والانتقالات الحالية سليمة؛ لا غلاف معلن في الإدارة أو شاشة auth ولا تسريب خاص أثناء transition |
| وجهة غير منفذة أو حق مفقود | لا صفحة فارغة/بيانات مزيفة/زر يوحي بالتنفيذ؛ حالة واضحة وخطوة موجودة مستقلة إن أمكن |

معيار التنظيم: المستخدم يميز القسم الذي يجد فيه الوظيفة، ويفهم وظيفة الإفادة من العرض، ويتم المهام بلا اعتماد على شرح تقني. تقييم مستخدم/مالك فعلي لجودة ذلك مستقل عن passing tests، ولا يستعاض عنه بنسبة شكلية أو حكم آلي من أسماء الملفات.

## 7. التحقق والبوابات والتبعيات

أثناء التطوير: اختبارات JS المتأثرة عبر Node24 للـinquiry/presentation وconsumer المباشر؛ `test:visibility` إذا تغير رأس SPA أو الانتقالات، وفق [خريطة الأوامر](../../BUILDERAD_TEST_EXECUTION_RATIONALIZATION.md#canonical-verification-commands). تشغيل ما يغطي السلوك المتأثر، ثم إعادة الفاشل/المتأثر فقط بعد التصحيح. عند فشل gate يثبت آخر passing baseline وبيئته والفروق قبل توسيع التشخيص.

متصفح التطبيق الحقيقي عبر entry point المعتمد `scripts/Test-GoalsSpa.ps1 -Phase Browser -BrowserSelection businesses` في بيئة الاختبار المعزولة؛ build واحد مناسب للمرحلة، وproof build فقط عندما تحتاجه الأدوات مع إعادة production قبل قبولها. تضاف source/account/auth selections بحسب تأثير الغلاف الفعلي؛ لا تدعى تغطيتها من businesses وحده. فشل أداة معاينة HTML في هذه المحادثة لا يجيز تجاوز سياستها ولا يعد فشل التطبيق، ولا يلغي requirement متصفح التطبيق لاحقًا عبر مساره المعتمد.

حماية السلطة الحالية تعاد الاستفادة من أدلتها ضمن نطاقها؛ تغييرات activation/العزل تستلزم الفحوص المتأثرة، ومنها isolated PHP `InquiryEvidenceAdmissionTest|InquiryEvidenceConcurrencyTest|BusinessSurfaceTest` عند مساس سلوكها. `CoreDependencyBoundaryTest` و`ArchitectureSourceOptionalityTest` تُشغّلان ضمن البوابات المنطبقة، ولا يُدعى نجاحهما من مراجعة وثائق.

القبول النهائي للحزمة الإنتاجية يتطلب gates Foundation المنطبقة على المرشح النهائي: workflow `.github/workflows/foundation.yml` عند تفويض النشر Git، أو entry point Windows المعزول `-Phase Foundation` إن تعذر hosted دون نشر غير مفوض. نتيجة Foundation لا تغطي browser lifecycle تلقائيًا ولا تمنح نشرًا. لا اختبارات شاملة للتطبيق في مرحلة الوثائق الحالية. يبقى `BACKEND_VERIFIED`, `UI_INTEGRATED`, `BROWSER_VERIFIED`, قبول البوابة النهائية وجودة العرض مستقلة.

التبعيات: هذا المرجع المنضبط، frozen map، قرار موضع BF03، المصدر/السلطة/المظهر/الترجمة الحالية، وبيئة verification المعزولة. لا حاجة لعميل حقيقي أو مزود مدفوع أو SQL جديد لتنفيذ هذه المواءمة؛ قد تظل خدمات منتج أخرى معلقة على أدلتها الخاصة.

## 8. حدود الإذن ومخرج التسليم التالي

المستثنى: SQL/API/migrations/permission semantics، CRM والتتبع الفردي، الإسناد/الحساب المالي/تجميع استفسارات جديد، محرك Targeting/Spend/decisions، live providers/حسابات/شراء، اشتراكات وحصص، تطبيق موازٍ، إعادة تصميم الإدارة، commit/push/merge/deploy دون إذنها.

عند تفويض `BA-ADVERTISER-UX-C01` بالاسم ينفذ غلاف وملاحة وعرض BF03 فقط داخل envelope أعلاه، ويسجل أي توسع لازم وأثره قبل تغيير عقد محمي. لا يعاد طلب اعتماد أسماء الأقسام أو أصل المعمارية دون دليل جديد. التسليم: diff محدد، behavior evidence، لقطات الحالات، الاختبارات والrevision/dirty state التي تغطيها، حدود التحقق والملاحظات المتبقية. **هذه المرحلة تنتهي بمرجع ومواصفة قابلين للمراجعة؛ تنفيذ Vue الإنتاجي لم يبدأ.**
