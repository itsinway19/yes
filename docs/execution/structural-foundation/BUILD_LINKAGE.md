# استمرار البناء — المنظومة والتبعيات قبل تنفيذ الحزم

التاريخ: 6 نوفمبر 2026. متابعة لتوجيه المالك في المحادثة بشأن ترابط جميع الوظائف والتعلم والتوصيات والأتمتة وAI. الحالة: **`CONSTRUCTION_PATH_RECONCILED / NO_NEW_PRODUCT_IMPLEMENTATION`**.

هذا سجل تشغيل مكمل لـPROGRAM، لا معمارية بديلة ولا برنامج دراسات جديد. المرجع المحلي `e2fd972985be3c1bb7c9d6a80b73b23a45281096`. أُعيد استعمال التدقيق وأدلة نسخته ودراسة المخاطر والمصادر؛ لم نعد تشغيل Foundation أو نفحص حسابًا أو بيئة إنتاج أو نحدّث خيارات التقنية في هذه المتابعة.

## 1. تصحيح مسار العمل

كان جعل `FIRST_USE_CASE_SELECTION_REQUIRED` خطوة حاكمة لكل عمل تأسيسي في المراجعات المحلية الأخيرة تضييقًا غير صحيح. PROGRAM نفسه يقرر بناء المسؤوليات المعروفة دون جعل أول ميزة حاكمة للمعمارية، وتوجيه المالك يشمل المنصة كاملة. لا نعيد تنظيم BuilderAd كلما طُرحت توصية أو متجر أو مصدر أو تعلم.

من الآن يُختار العمل التالي من البرنامج والتبعيات الفعلية. يجوز تأهيل أساس مشترك لحاجات معروفة ومتباينة دون ربط قبوله بميزة مدفوعة منفردة أو اختيار قطاع أول. **عند تنفيذ قدرة أو تغيير عقد مادي** يلزم تحديد المستهلك والسلوك والمدخلات والحقوق والتوابع المتأثرة؛ لا ترخيص بذلك لبناء إطار عام فارغ. تظل معايير الكفاية بحسب القدرة والإدخال التدريجي ومصدر الدليل والإجراء الصحيح محفوظة، ولا يعاد بناء Business أو صلاحياته.

الآراء الأربعة المقدمة تدعم هذا التصحيح بدرجات متقاربة: الأول يوضح فصل الهيكل عن تفاصيل الوظائف، والثاني يوضح أن الأقسام ليست أنظمة حقائق مستقلة، والثالث الأنسب في استكمال البرنامج الحالي دون حوكمة موازية، والرابع أوضح في التعلم وAI والتشغيل كمسارات متصلة. لا نأخذ منها مراحل مغلقة، أو محرك قرار عالميًا، أو وعدًا بأن الحدود لن تحتاج امتدادًا مشروعًا مستقبلًا. ادعاءات فحص GitHub داخلها لا تُقدَّم كفحص جديد نفذناه في هذه المتابعة، وعبارات اعتمادها ليست تفويض كتابة أو دمج.

## 2. خريطة المنظومة المعروفة وحدودها

هذه خريطة مسؤوليات، وليست أسماء خدمات/جداول جديدة. خريطة CAPABILITY_COVERAGE الحالية تضم87 صفًا من جداول Blueprint المحددة، وتوضح بنفسها أن الارتباطات على مستوى الأسر الوظيفية وليست تحققًا فرديًا. لا نحولها آليًا إلى تبعيات إلزامية أو قبول87 وظيفة. الأقسام السبعة الحالية واجهات عمل فوق المسؤوليات؛ ثماني مجموعات المصدر التاريخية ليست تغييرًا لعدد وجهات التنقل المقبولة.

هذه الأسر لا تغلق حدود المنتج. معرفة جديدة قد تكشف وظيفة أو علاقة أو تصحيحًا مشروعًا؛ حينها تسجل في البرنامج بمصدرها وأثرها بدل تجاهلها لعدم وجود اسمها في الجدول أو إعادة ترتيب المنصة كلها. الإعلان وظيفة رئيسية، والتحويل والوفاء والاحتفاظ والتوصيات والتعلم ليست ملحقات منسية؛ تتعاون لتحسين نتيجة النشاط بحسب غايته.

## 3. ما معنى أن التبعيات سليمة قبل البناء؟

لكل تبعية مؤثرة دليل صلاحية **في النطاق الذي ستستعمله الوظيفة الجديدة**، وليس نجاحًا قديمًا باسم المكوّن فقط. نعتمد الاختبارات المطابقة للنسخة والبيئة والعقد، ونفحص ملاءمة المعنى للامتداد. إن بقي عيب مثبت أو فشل لازم أو سلطة غير محسومة في تلك التبعية فلا يوصف الفرع بأنه جاهز ولا يُتجاوز بfixture أو تخفيف اختبار. نواصل الفروع المستقلة؛ لا تحويل ذلك إلى شرط اكتمال جميع وظائف المنصة أو جميع دراساتها قبل أي إضافة.

| الرابط | متى يكون لازمًا؟ | ما الذي يثبت قبوله وما الذي يوقف الفرع؟ |
|---|---|---|
| هوية/حق مورد → كل استعمال محمي | عند القراءة والكتابة أو الأثر | مسار سلطة تشغيلي، عزل ورفض وسحب وإعادة تأهيل عند الأثر؛ issuer غير مثبت ليس حقًا افتراضيًا |
| سياق نشاط/عرض → حكم متخصص | عندما تغير تلك المعلومات الحكم | معنى ونسخة ومالك ومدخل مؤهل، اختلاف مؤثر وثبات مبرر؛ لا يلزم هدف أو ملف مكتمل لكل قراءة |
| مصدر → دليل أو مادة تحليل | إذا اعتمدت النتيجة على بياناته | وصول وعينة مناسبة وschema ووحدة وتغطية/تحديث وحقوق/تكلفة/فشل؛ ذكر API أو vendor لا يثبت تشغيله. النموذج التجريبي يعلن synthetic ولا يثبت السوق |
| دليل ومنهج → تشخيص/توصية | إذا كان الاستنتاج متعلقًا بهما | صلاحية الدليل والطريقة لهذا السؤال والقطاع/الوحدة واللغة/السوق؛ بدائل واختبار نقض وحدود استدلال |
| نتيجة تجارية → عائد أو تعلم نتائج | إذا وعد الحكم بقياسها | واقعة ومصدر ومطابقة ومقام ونافذة ونضج وتصحيح؛ المنسوب أو المصرح ليس تحققًا مستقلاً |
| قرار/سياسة → تنفيذ | إذا وقع أثر خارجي أو مالي | تفويض المورد والفعل الحاليان، قراءة الحالة وحدود المزود، إيصال ومصالحة المجهول؛ لا يبيح حق القراءة الكتابة |
| تشغيل/اشتراك → خدمة مدفوعة/مجدولة | عند استعمال قدرة تعتمد عليهما | سياسة تكلفة/حصة مناسبة وبيئة/عمال/رصد مؤهلون؛ لا يشترط اكتمال الفوترة لحفظ تصريح محلي مستقل |
| نتيجة/تقييم → تغيير المنهج أو التوصية | عندما يستعمل التعلم لتغيير السلوك | معيار ونطاق وثقة وإصدار وحق وإمكان مراجعة/سحب؛ لا تحديث خفي ذاتي أو تدريب عابر للأنشطة |

## 4. سجل الارتباط المطلوب لكل وظيفة قبل برمجتها

يضاف إلى سجل الحزمة في IMPLEMENTATION_PROGRESS/بطاقتها القائمة، لا نظام runtime أو ملف دراسة جديد لكل سؤال:

1. **الوظيفة والقيمة والسطح:** ما الذي يستطيع المستخدم إنجازه، لمن وأين، وما الذي لا تعد به النتيجة؟ الأساس الداخلي يحدد المستهلكين المعروفين وسبب اشتراك حاجتهم.
2. **مالك كل حقيقة وقرار وفعل:** الكاتب/القارئ، العقد والملفات الحالية، وما يعاد استعماله وما يتغير؛ snapshots/projections المؤهلة مسموحة وليست كتّاب حقيقة موازين.
3. **المدخلات والتبعيات:** لازم/مشروط/غير منطبق مع السبب، نسخة/زمن/هوية/وحدة، مصدر الدليل وطريق الحصول عليه وحقوقه وتكلفته، والمنهج المناسب؛ لا تبديل lineage بسبب تشابه أسماء.
4. **المخرجات والمستهلكون:** من سيستعملها في الأقسام أو الأدوات أو الأتمتة أو التعلم، وبأي معنى وحق، وما الذي لا يجوز استنتاجه منها؟ لا انتقال ضمني لصلاحية.
5. **أثر التغيير:** ماذا يبطل أو يتقادم عند التصحيح أو السحب أو تغير السياق/المصدر/المنهج؟ ما الاختبارات والمستهلكون الحاليون المتأثرون؟ التعلم لإصدار لاحق وليس حلقة اعتماد دورية تمنع التشغيل.
6. **الأوامر والفشل:** التزامن وidempotency وتعارض النسخ و422/409 والمجهول، إعادة التأهيل والمصالحة؛ لا عمل ثقيل تحت قفل أو أثر بديل عند فقد الرد.
7. **القبول:** نجاح ورفض وعزل وتاريخ وترقية/مخطط نهائي حيث يلزم، سلوك المستهلك الحقيقي، UI/RTL/متصفح وفهم، قياس الأداء المتأثر؛ تظل BACKEND_VERIFIED/UI_INTEGRATED/BROWSER_VERIFIED والأثر التجاري حالات منفصلة.
8. **مرجع التنفيذ والتوازي:** baseline وحالة الملفات والعقود المشتركة ومالكها والتبعيات مع الأعمال المفتوحة؛ دليل الحالة المدمجة الفعلية قبل قبولها. لا تقبل حزمة من اختبارات كل فرع منفردًا إذا تغير عقدهما معًا.

ليس مطلوبًا تشغيل كل بوابات المخاطر26 لكل وظيفة؛ تُحدد المنطبقة بالسبب، وتبقى الحدود المشتركة محمية. لا يمر «غير منطبق» إذا استعمل الكود فعليًا الدليل أو الصلاحية أو المورد. لا يبدأ تنفيذ وظيفة بتبعيات حاسمة مجهولة ثم تكتشف بعد بنائها.

## 6. ما أُغلق وما بقي

أُغلق تضارب التوجيه بين «أول ميزة» و«خريطة المنظومة»: البرنامج الحالي هو مرجع استكمال البناء، والحالة التجارية تعيّن سلوك الحزمة التي تُنفذ ولا تختزل خريطة المنتج. تعديلات الأولويات المحلية بتاريخ6نوفمبر ومصفوفة الكفاية ودراسة المخاطر تبقى مراجع بنطاقها، ولا تستبدل PROGRAM أو تحول FIRST_USE_CASE_SELECTION_REQUIRED إلى حظر عام على العمل التأسيسي.

لم يُكتب منتج جديد ولم تُحسم صلاحية issuer أو مصدر/متجر أو نموذج أو فعل غير مؤهل. لم تتحول87 صفًا إلى وظائف جاهزة أو كل المخاطر إلى إخفاقات حالية. لا ننشئ معمارية أو قائمة قدرات مغلقة باسم التصحيح. نحتفظ بالدراسات المؤهلة ونستخدمها عندما تؤثر، ونوسع فقط الفجوة المعرفية المحددة، لا نعيد المسح العام.
