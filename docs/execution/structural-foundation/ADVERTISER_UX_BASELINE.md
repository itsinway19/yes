## 3. عقد الاحتراف البصري والسلوكي

1. **هرمية واحدة:** هوية التطبيق/النشاط ← قسم رئيسي ← تنقل محلي عند الحاجة ← قائمة/تفاصيل/تحرير. لا ثلاث قوائم متنافسة، ولا عنوان القسم مكرر فوق نفسه. مكان الوظيفة ثابت عبر الأنشطة، لكن محتواها ومعيار فائدتها يتخصصان.
2. **مقاسات مشتركة:** body ‏14px، نص ثانوي مقروء لا يقل عادةً عن 12px، عنوان صفحة 22–24px، عنوان مجموعة 15–16px. تُطبّق أحجام المرجع بأدوار CSS مشتركة، لا تعديلات inline متفرقة. الأرقام المهمة ليست تبريرًا لبطاقات ضخمة.
3. **شبكة ومسافات:** درجات 4/8/12/16/24/32px؛ شريط جانبي مدمج وشريط هوية قصير، عمودان للمحتوى عند كفاية العرض وعمود واحد على الهاتف. الجدول وحده يمكن أن يمرر أفقيًا عند الحاجة، لا الصفحة كلها. لا تثبيت عرض يضغط العربية أو يخفي الإجراءات.
4. **هوية واحدة:** `GlobalAppearance` و`public/brand/theme.css` و`theme.js` و`BrandLogo` ملاك اللون والمظهر والعلامة. تُترجم ألوان HTML إلى متغيراتهم؛ لا مخزن لون/ثيم أو علامة مستقلة. خطوط محلية بغطاء عربي وRTL/LTR منطقي.
5. **أنماط متسقة:** ترويسة وإجراء أساسي واحد بحسب المهمة؛ الإجراءات الثانوية مجمعة، والخطرة منفصلة بتأكيد مناسب. نفس أدوار البطاقات والجداول والنماذج والتنبيهات في جميع الأقسام. تفاصيل المصدر/التعريف/الإصدار تُفتح عند الحاجة وتبقى كاملة.
6. **حالات حقيقية:** تحميل، فارغ، غير معروف، ممنوع، نتيجة أمر غير مؤكدة، تعارض، فشل تحديث، وقيمة معروفة بما فيها الصفر. لا أرقام تعويضية أو فقد مسودة أو إعادة أمر تلقائية أو رسالة نجاح تعلو على فشل إعادة القراءة.
7. **وصول:** أهداف لمس ≥44×44px على الهاتف، تحكم لوحة مفاتيح، focus ظاهر وإرجاعه بعد الإغلاق، ESC، حوار مسمى مع حصر التركيز وخلفية غير تفاعلية، تقليل الحركة، تباين WCAG AA للنصوص/التحكم. إن لم تنفذ ARIA tabs كاملة تستعمل ملاحة محلية عادية مسماة.
8. **بوابة مرئية:** لقطات الصفحات الفعلية وأهم الحالات عند 390 و768 و1440px، عربية/إنجليزية ونهاري/ليلي؛ لا تداخل أو قص أو تمرير أفقي للصفحة. مراجعة اتساق عابرة للأقسام وإتمام مهام فعلية تسبق وصف «احترافي متحقق»؛ syntax/build/tests وحدها غير كافية.

## 4. قرار BF03 وحدود القيمة

**الموضع الأساسي المحدد:** «النشاط والفريق والإعدادات ← البيانات والإفادات ← إفادات الاستفسارات». يستعمل المورد الحالي Business وسلطاته، لا نقلًا إلى Workspace أو حق إدارة المصادر. أسباب الترجيح: الأصل إفادة خاصة صرّح بها النشاط، والوظيفة الحالية حفظ/قراءة/تصحيح وتاريخ؛ ليست تتبع عملاء أو اتصال مزود خارجي. استبعاد وضعها تحت «المصادر» لا يمنع مستقبلًا وصل مصدر مشروع بعقد مستقل.

مدخلها يبقى ظاهرًا للمخول داخل النشاط، وقابلًا للاكتشاف بالبحث والتوجيه السياقي. لا يلزم المرور بصفحة تشرح خدمات مستقبلية للوصول إلى السجل. تستخدم عبارات «تسجيل بيانات مجمّعة لفترة وقناة» و«تصحيح الإفادة»، ولا تستخدم «إضافة استفسار» بمعنى سجل فرد. الإتاحة والعرض وإرسال كل إجراء تبقى خاضعة لحقوقها المستقلة.

**هذا ليس خفضًا لقيمة الاستفسارات:** العدد وقناة التسجيل والفترة والتغطية قد تقدم منفعة كبيرة. العرض الحالي لكل مجموعة المؤهلة يبقى مفهومًا، ولا تختفي القيم داخل بيانات تقنية. يمكن ربط «المبيعات والتحويل» و«النتائج والعائد» بهذا السجل؛ لكن التجميع عبر مجموعات أو التشخيص أو الإسناد أو عرض نتيجة مشتقة يحتاج العقد والحقوق والتغطية وعدم التداخل المنطبقة. لا تعني صلاحية القراءة سلطة تحليل/تصدير عامة. قناة المكالمة/النموذج/الرسالة ليست مصدر الاكتساب الإعلاني؛ الأخير يبقى مجهولًا دون دليل مستقل.

لا تُمس أسماء الأفعال `business.inquiry_evidence.record/correct/read`، السياسة `own_private_statement`، الأصل/الإصدارات، SQL/API، الاستحقاق أو حفظ البيانات. الإخفاء عند سحب القراءة والتفعيل الجديد وإبطال الردود المتأخرة والـimmutable command والمسودة داخل document-memory تبقى شروطًا سارية. لا localStorage لإفادات إنتاجية أو سلطة. المرجع التفاعلي الجديد لا يثبت تطبيق تلك الشروط خادميًا.

## 6. أثر المعرفة السابقة وما لا يعاد بحثه

أعيد استعمال `BUSINESS_WORKSPACE_UX.md` وعقد UX الموجود لحفظ المهمة/التفاصيل/العودة والمسودة، لا نسخ خمس وجهات واجهة قديمة كخريطة منتج أبدية. أعيد استعمال BF03 وسجل `IMPLEMENTATION_PROGRESS.md` لتحديد معنى الإفادة والحقوق والتاريخ؛ رُفض تحويل وجوده الهندسي إلى أولوية تجارية عامة. أعيد استعمال البرنامج وفصل Targeting/Spend/الأثر، ومبدأ BA-CAEI v1.1 الخاص بتعدد مداخل العمل؛ رُفض اشتراط هدف أو اتصال لكل منفعة. لم تُجر مقارنة تجارية جديدة للمنافسين أو مراجعة كاملة للأرشيف.

الفجوة الفعلية تنظيم/اكتشاف وسلوك انتقال مؤهل، وليست نقص CRM أو SQL. اختبارات الفصل: هل يجد المستخدم الإفادة دون الاعتقاد أنها تتبع أشخاص؟ هل يفهم العدد والمجهول والقناة؟ وهل يمنع الرجوع/تبديل الهوية/سحب القراءة كشف المحتوى؟ تُراجع الحدود إذا تغير عقد BF03 أو أضيف استيراد/تحليل/نتيجة حقيقية، أو أثبت اختبار مستخدم عجز الخريطة عن إنجاز مهمة. اختلاف تفضيل جمالي وحده لا يعيد فتح تنظيم مثبت.

## 7. العمل التالي وحدود هذه المرحلة

الحزمة البرمجية التالية المحددة هي [مواءمة ملاحة المعلن ونقل إدارة BF03](ADVERTISER_UX_IMPLEMENTATION_PACKAGE.md). هي ظرف قابل للمراجعة، لا تنفيذ حاصل ولا تفويض نشر. تُحفظ مواضع البرنامج السابقة بتاريخها؛ هذا السجل يحدّث اختيار العمل الحالي ولا يمحو السند التاريخي.

بعدها يرشح **تفعيل صادق لمعلن جديد** كأول شريحة منتج للتأهيل: تعريف النشاط، منفعة متاحة فعلًا، فهم الحد والخطوة التالية؛ لا ترقية استكمال ملف إلى قيمة تجارية مثبتة. له أقل تبعية غير محسومة من البديلين التاليين ويجب أن ينتج مهمة مفيدة فعلًا، وإلا تعاد المفاضلة. ربط واقعة تجارية بالأدلة الإعلانية يحتاج عقد وقوع ومصدر/حق/ربط مؤهل؛ «أين عملائي؟» أو المنافسة تحتاج سؤالًا محدودًا وطريقة ودليلًا وحقوقًا للسوق المختار. لا يوقف غياب دليل فرع بقية الفروع، ولا يصبح BF03 شرطًا لأي منها، ولا يفوض هذا الترجيح تنفيذ الشريحة التالية.
