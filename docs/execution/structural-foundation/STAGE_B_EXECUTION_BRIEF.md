## قرار المالك عند اعتماد التكليف

أعتمد PROGRAM مرجعًا لبرنامج البناء ضمن نطاقه الموثق، ومعه BUILD_LINKAGE وسجل التنفيذ والمعمارية والعقود المعتمدة. أفوض الانتقال إلى Stage B للتحقق الموجز واختيار وتنفيذ أول حزمة محدودة تستوفي تأهيلها وتبعياتها وسلطتها ضمن هذا البرنامج.

لا يُعد ذلك قبولًا تلقائيًا لعقد مستقبلي أو تفويضًا بتغيير معنى أو صلاحية محميين، أو تشغيل حسابات/موارد مدفوعة أو تعديل بيانات المالك أو المعاينة أو الإنتاج، أو commit/push/merge/deploy. ينفذ العمل الروتيني المأذون دون إعادة طلب اعتماد أصل المعمارية؛ يرفع فقط القرار المحمي المحدد عند لزومه، بعد إعداد تغيير واضح قابل للمراجعة.

## 1. الهدف ونطاق المنظومة

انتقل من التخطيط إلى بناء فعلي متدرج يحفظ قابلية استكمال BuilderAd، دون تكرار الحقائق أو اختراق الحقوق أو إعادة تأسيس كلما أضيفت وظيفة. لا تُنشئ دراسة أو برنامج حوكمة أو معمارية بديلة، ولا تحول قائمة الأقسام إلى خدمات/قواعد بيانات مستقلة.

تظل المنظومة المعروفة حاضرة في اختيار الحزمة: هوية النشاط والقطاع والتخصص والعروض والأسواق والأهداف والقيود؛ الفرق والوكالات؛ مصادر الإعلانات الخمسة والمتاجر والموقع والتواصل ومصادر السوق؛ المعرفة والأدلة والنتائج؛ السوق والعملاء والمنافسة والوصول؛ المواد والخطط والإعلانات؛ التحويل والبيع والوفاء والتحصيل والإلغاء والمرتجعات والتكاليف؛ الاقتصاد والعائد والاحتفاظ؛ التشخيص والتوصيات والقرارات والتجارب والقياس؛ الأفعال والمراقبة والأتمتة؛ AI والبحث والمساعدة والتعلم والتحسين؛ الواجهات والإدارة والاشتراكات والتشغيل.

هذه خريطة مفتوحة لا قائمة مغلقة ولا أمرًا بتنفيذها كلها مقدمًا. يجوز تأسيس عقد مشترك لحاجات معروفة ومتباينة دون اشتراط نجاح ميزة مدفوعة واحدة، لكن يلزم مستهلكون وسلوك ممثل يبرران التغيير. لا تجعل أول قطاع أو ميزة أو مصدر حاكمًا للمعمارية، ولا اكتمال كل المستقبل شرطًا للحزمة المستقلة.

مراجعة الكود لا تعوض العلم المتخصص؛ ووجود SDK أو schema لا يثبت صلاحية المنهج. فرّق بين الخاصية المنشورة، ورأي الخبير، وعينة المصدر، والفرضية، وسلوك الكود، ونتيجة الاختبار، والأثر التجاري. تحقق من مصدر/عينة/حقوق وتغطية وحداثة وتكلفة وفشل البيانات قبل بناء ادعاء يعتمد عليها؛ يجوز اختبار عقد ببيانات اصطناعية معلنة دون ادعاء أنها تثبت السوق أو الترخيص أو المنفعة المدفوعة.

## 4. اختيار الحزمة من التبعيات

استعمل البرنامج وخريطة الترابط والمطابقة القائمة لتحديد النقص التالي، مع مقارنة محدودة بأقرب بديل، دون تدقيق معماري شامل جديد. لا تفترض أن F02/D01 أو G-01 أو ربط متجر أو تشخيص إعلان هو الأول تلقائيًا. افحص حدود سياق Business والعرض والسوق، وحقوق استعمال المصادر، والنتائج والمستهلكين بحسب الأدلة؛ الموجود الكافي يعاد استعماله.

اختر وفق: حاجة مثبتة؛ نوعية وعدد المستهلكين المعروفين؛ أثر التأخير على الأخطاء وإعادة العمل؛ ملاءمة العقد والحق والمصدر والمنهج؛ إمكان الاختبار والإغلاق؛ وعدم تعارض العمل المتزامن. لا تختر حزمة شكلية لتجاوز عائق حقيقي، ولا تجعل عائق فرع معين يوقف عملًا مستقلًا مأذونًا.

للحزمة المختارة سجل قبل الكود:

1. المسؤولية والكاتب والقارئ ومالك الحقيقة/القرار/الفعل، والسلوك والقيمة أو المستهلكون التأسيسيون المعروفون.
2. المدخلات ومصادرها ونسخها وحقوقها ووحداتها، والمخرجات والمستهلكون في الأقسام والأدوات وAI والأتمتة والتعلم.
3. تبعيات لازمة/مشروطة/غير منطبقة، مع سبب ودليل صلاحيتها **للاستعمال الجديد**؛ والتصحيح والسحب والانتهاء والمجهول.
4. الموجود المعاد استعماله، وأقل delta، والملفات والعقود والمخطط والمستهلكون والأعمال المتوازية المتأثرون.
5. اختبارات السلوك الفارقة وحالات الرفض والعزل والتاريخ والتزامن والترقية والواجهة بحسب الأثر، ومخاطر سجل الهندسة المنطبقة فقط.
6. شرط البدء والقبول، وحدود التفويض، ومعيار الإيقاف، والحزم التي تفتحها النتيجة أو لا تزال محجوبة.

استوفِ بوابة تأهيل الحزمة G8 وفق البرنامج والتفويض الأحدث، لا باختراع بوابة بديلة ولا بنقل نتيجة حزمة قديمة. `G8_FIRST_PACKAGE.md` سجل حزمة تاريخية بنطاقها وحالتها؛ لا يثبت جاهزية الحزمة الجديدة أو يفرض تنفيذ تلك الحزمة المؤجلة أولًا. قبول هذا التكليف لا يحسم issuer/حق استعمال جديدًا أو قارئًا خاصًا أو سياسة أثر مالي غير معتمدة.

## 5. التنفيذ داخل المهمة نفسها

عند اكتمال تأهيل الحزمة ووجود تفويضها، نفذ أقل تعديل معماري وبرمجي صحيح ومتكامل في مساحة معزولة، مع حفظ الحالة المحلية وأدلة المرشح. لا تتوقف عند إنتاج خطة أخرى، ولا تعِد طلب اعتماد أصل المعمارية لقرار روتيني داخل النطاق. التغيير المحمي فقط يرفع كقرار محدد قابل للمراجعة؛ استمر في العمل المستقل المأذون.

لا تنشئ هوية Business أو Workspace أو محرك صلاحيات/حقائق/قرار موازيًا، ولا framework عامًا للقطاعات أو المصادر أو AI دون حاجة مثبتة. لا تُدخل provider/AI implementation إلى Core المحمي، ولا تمدد D2 إلى خبير شامل أو تُجبر كل تشخيص على Targeting/Spend. تحافظ المصادر على معناها وتبقى قابلة للاستبدال ضمن الحقوق؛ الاستقلال لا يضمن استمرار بيانات سُحب ترخيصها.

احفظ تعدد الأنشطة والعروض والأسواق، والفرق بين الحالي والمستهدف والخدمة، والتصريح/الملاحظة/الاستنتاج، والتحويل/البيع/التحصيل/الربح/السببية. لا تعِد تفسير التاريخ أو codec أو حق قديم بصمت. الاتصال ليس حق استعمال أو كتابة. كل فعل له مورد وحالة وتفويض وإيصال ومصالحة؛ لا أمر بديل تلقائيًا بعد نتيجة مجهولة.

AI والأتمتة والتوصيات والتعلم أجزاء من التصميم منذ البداية؛ يُنفذ منها ما تأهلت مهمته وأدواته وبياناته وقياسه وكلفته وسلطته. لا يُحصر التعلم في تدريب نموذج، ولا يفترض حق التدريب أو المشاركة من حق التحليل. لا تفرض تقنية لمجرد الحداثة أو قيود استضافة حالية؛ اختَر ما يلائم المعنى والأمان والأداء والتكلفة والتشغيل، مع إمكان السحابة والخدمات المناسبة، وتحقق البيئة المختارة قبل إطلاقها.

للقابلية الظاهرة للمستخدم: استكمل السطح والمستهلك الحقيقي في نطاق الحزمة، لا جداول/أصناف فارغة أو Backend بلا الواجهة التي يتطلبها العقد. العربية واضحة وRTL وحالات النقص والرفض والتعارض والمجهول مفهومة؛ لا مصطلحات النظام بوصفها مهامًا للمعلن.

## 6. اختبارات القبول والدليل

حدد معيار السلوك قبل التنفيذ، واستخدم اختبارًا فارقًا مناسبًا يكشف غياب الوظيفة أو خطأها، دون اختبارات شكلية تطابق التنفيذ. نفذ الاختبارات المنطبقة للكتابة والقراءة والرفض والسحب وعزل نشاطين ووكالة/موظف، وتغير سياق مؤثر وثبات غير المؤثر، والتصحيح وإعادة أهلية المشتقات، والتزامن والرد المتأخر والتكرار والمجهول.

عند تغير SQL/عقد مشترك: افحص المستهلكين والتعريف النهائي وترتيب reload، واختبر fresh/upgrade ببيانات تاريخية وحقوقها وإيصالاتها وبصماتها. لا قاعدة المالك أو المعاينة لاختبارات مدمرة. عند أثر API/Types/Vue حدّث العقود واختبر المكونات والمتصفح الحقيقي والوثيقة الجديدة وتبديل السياق وRTL بحسب المسار.

عند ادعاء أداء أو ترجيح تقني يعتمد عليه، قِس workload/بيئة ممثلة مع baseline وموارد وأدوار معلومة؛ لا افتراض اختناق أو زيادة مهلة/ذاكرة أو تعطيل حماية لإخفاء إخفاق. لا تغير RLS أو شروط التزامن أو الادعاء التجاري لتجاوز الاختبار.

أعد استعمال الأدلة التي بقيت مكافئة، وشغل المتأثر بعد التصحيح. نفذ الحراس والبوابات الإلزامية بحسب التغيير على المرشح النهائي؛ Foundation المستضافة مفضلة حين يُفوّض push، دون إعادة محلية مكافئة تلقائيًا. إذا كان النشر غير مفوض، جهز الأمر والبوابات الباقية وصرح بأنها غير منفذة؛ لا PASS لبوابة معلقة.

أبقِ BACKEND_VERIFIED وUI_INTEGRATED وBROWSER_VERIFIED وقبول المنفعة التجارية والإنتاج منفصلة. نجاح البناء أو fixtures أو سلامة manifest لا تثبت رحلة مستخدم أو حق مصدر أو أداء نموذج أو زيادة مبيعات. احفظ الإخفاقات وتفسيرها وتصحيحها بجانب النجاحات المطابقة للنسخة النهائية.

## 7. التسليم والاستمرار

حدّث IMPLEMENTATION_PROGRESS وسجل الحزمة القائم، وسلم بإيجاز:

- الحالة الفعلية المحلية والمستضافة والعمل المتعارض وحدود الدليل.
- خريطة الحزم المختصرة وتبعياتها والتوازي الآمن، والحزمة المختارة وسبب تقديمها على البديل.
- سجل أثر الدراسات على العقد/المنهج/الاختبار، وما بقي مشروطًا أو غير مقروء في نطاقه.
- التغيير البرمجي الفعلي والملفات والعقود، أو أصغر مانع حقيقي ومحاولة حسمه المأذونة؛ لا تعديل شكلي.
- الاختبارات والنتائج والفشل وغير المنفذ ومرجع الحالة النهائية والبوابات المتبقية.
- الحزمة التالية التي أصبحت مؤهلة فعلًا والقرارات المحمية المحددة فقط. لا تفويض نشر/دمج تلقائي؛ يجوز إعداد وصف PR محلي قابل للمراجعة دون إرساله.

أوقف عمليات الاختبار والخدمات التي بدأتَها إلا ما طلب المالك إبقاءه. لا تعِد تأسيس المنصة أو دراسة كل الأرشيف أو كتابة تقرير أولويات جديد بعد كل حزمة. يبدأ التنفيذ عند تفعيل هذا التكليف واستيفاء حدود الحزمة، ثم يستمر بالتبعيات المثبتة.
